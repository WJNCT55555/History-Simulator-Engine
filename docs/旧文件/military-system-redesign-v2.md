# 《自由未烬》军事系统重构方案 v3.1 Final

**主题：来源归属武装池 × 两场战争参数化 × 共和国/国民军内部政治 × 五月事件式决裂**

- 文档状态：最终设计基线；规则已全部锁定，不覆盖 v1.1
- 设计基线：当前工作区与 `military-integration-design.md` v1.1
- 核心范围：1934 年阿斯图里亚斯起义、1936 年西班牙内战、共和阵营五月事件、国民阵营统一法令
- 首要约束：不设置“中央服从度”或“动态政治授权”

---

## 0. 方案结论

新版军事系统采用三层结构：

1. **阵营层**：共和国、国民军、工人联盟，以及架空决裂后才出现的第三阵营。阵营拥有地图补给、工业能力和指挥点。
2. **武装库存层**：共和国正规军、突击卫队与国民警卫系统共用一个国家武装池；每个实际拥有民兵的党派各有一个民兵池。每个池只有三个库存：**人员、火炮、坦克**。
3. **地图部队层**：已经从库存池动员到前线的具体单位，保留来源池、兵种系统、人员、火炮、坦克、士气和训练/编制质量。

玩家在战争地图上代表当前阵营的联合指挥部，采用**纯全指挥**：可以直接移动和使用本阵营全部单位。党派矛盾不通过命令加价、抗命概率或隐藏服从值表现，而通过以下渠道表现：

- 人员和装备归谁所有；
- 国家生产与外援如何分配；
- 民兵是否接受整编、资产是否转入人民军；
- 各政治集团的军事份额与政治话语权是否失衡；
- 联盟凝聚力是否跌入危机，并最终引发五月事件式内部武装冲突。

这使“玩家能够顺畅指挥战争”与“共和国并非单一政治主体”同时成立。

## 1. 不可违反的设计边界

### 1.1 已锁定规则

- 只有**实际拥有武装的实体**建立武装池；政党本身不因拥有议席、支持率或下属组织而重复生成库存。
- 民兵武装实体必须由一个处于 active 状态的真实组织承载；党派成立不等于民兵已经成立，组织成立也不自动生成超出历史事件投入的资产。
- CNT 的 `Comités de Defensa`（防御委员会）是战前组织与动员前置，不等于 `Milicias Confederales`。武装防御委员会后形成的前身实体可以拥有三项资产；只有防御委员会已经成立，1936 年 7 月的战争动员事件才能成立 `Milicias Confederales`，整池继承此前资产并激活 CNT 战时民兵；1934 年阿斯图里亚斯 CNT 地方防务组不得提前使用这一名称。
- PSOE/UGT、PCE、POUM、CT、FE 和 PNV 的民兵同样必须按历史时间建立对应组织，再激活其武装实体。非 CNT 组织完整进入状态、事件、存档与测试，但本阶段不显示在任何游戏 UI 中。
- 每个武装池只记录：`人员`、`火炮`、`坦克`。
- 共和国正规军、突击卫队、国民警卫队/国民共和国卫队共用一个**共和国国家武装池**，不各建储备池；地图单位以 `serviceType` 区分其战术性质与历史名称。
- 每个实际拥有独立民兵的政治力量各建一个民兵池；同一党派的不同纵队、团或地方支队不重复建池。
- 每个国家或党派池都把 `人员`、`火炮`、`坦克` 分成三个独立数值记录；不得合并成“总军备”或“装备度”。
- 共和国民兵军事化采用一条全局三级进度：`L0 自治纵队 -> L1 混合旅过渡 -> L2 共和国人民军`；升级同时作用于全部党派民兵池。
- 军事化采用克制档“直接战斗型”收益：L0 无修正；L1 为战斗力 `+5%`、有效士气 `+5`、伤亡 `-5%`；L2 为战斗力 `+10%`、有效士气 `+10`、伤亡 `-10%`。修正从共和国全局状态动态派生，不写入单支部队。
- 达到 L2 时，共和国境内全部党派民兵、地区武装和国际纵队的三个资产栏及其地图部队在一次原子结算中共同并入共和国国家武装池，界面上的独立武装槽位统一折叠为“共和国人民军”；来源历史只保留在交易账本中。
- 军事化等级只能由指定历史事件及其条件推进；可重复军事卡不能购买或直接提高等级。
- L1 -> L2 是可拒绝的政治决断：接受后人民军化不可逆，并关闭五月危机中的武装抵抗选项；拒绝则停留 L1，并提高全国决裂风险。
- 新增资产按来源确定初始归属；跨实体转移必须由明确的分配、整编、缴获或解散行为完成。
- 分裂前采用纯全指挥，不设置友军自治、命令拒绝、中央服从度或动态政治授权。
- 地图历史驻防仍是战争开局基本盘；战前积累只提供额外骨干部队、预备池、重装备和质量修正，不推翻历史地理格局。
- 五月事件式冲突由联盟凝聚力过低触发；选择武装抵抗后立即升级为全国三方战争，不以巴塞罗那局部地图战的胜负作为前置条件。
- 第三阵营除继承转入省份的本地资源外，还按分裂后共和国与第三阵营各自控制城市的战略点数之比切分共和国中央补给和工业储备；既有外国援助暂停并重新判定接收方。
- 阿斯图里亚斯工人联盟固定采用党派分池：社会主义矿工、CNT 地方武装、共产主义武装各有一池，由玩家统一指挥；镇压方正规军、突击卫队和国民警卫系统共用共和国国家池。
- POUM 只有在已成立、仍合法、未遭镇压且 CNT-POUM 关系不低于 `70` 时，才整池加入第三阵营。
- 第三阵营不存在“守住东部后谈判承认”的独立胜利；共和国与国民军均进入败亡状态时即完成统一，不再要求额外控制一份战略城市清单。
- 三方战争中三个阵营始终两两敌对，不允许停战、共同作战或单独媾和。
- 任一阵营败亡时，其尚未被占领的全部省份一次性转交给败亡瞬间占有该阵营首都的国家；领土转移不等于部队、人员或重装备自动投诚。

### 1.2 明确保留的阵营资源

“实体池只有三项”不等于删除地图经济。以下仍属于**阵营公共资源**，不归某个党派武装池：

| 阵营资源 | 用途 | 与实体池的关系 |
|---|---|---|
| 补给 | 轻武器、弹药、燃料、运输和日常消耗的总抽象 | 征募和补充必须同时支付，避免“只有人就能成军” |
| 工业能力 | 建筑、维修、重装备生产与改装能力 | 生产完成后，火炮/坦克才进入来源规则指定的实体池 |
| 指挥点 | 每回合可执行的地图行动量 | 只限制行动数量，不表示政治授权 |

步枪不进入党派库存。轻武器短缺由阵营补给、开战动员系数和单位战斗训练度共同表现；这样既遵守三项池约束，也保留 1934 年起义与 1936 年民兵普遍缺枪的历史问题。

## 2. 玩家身份与核心循环

### 2.1 战时玩家身份

| 战争阶段 | 玩家代表 | 地图控制范围 |
|---|---|---|
| 阿斯图里亚斯起义 | 阿斯图里亚斯工人联盟革命委员会 | 工人联盟全部武装实体 |
| 1936 内战、共和国未决裂 | 共和国联合战争指挥部 | 共和国阵营全部单位 |
| 五月危机接受整编 | 共和国人民军最高指挥部 | 共和国阵营全部单位 |
| 五月危机升级并选择抵抗 | 革命防御委员会 | 转入委员会的实体与单位；共和国其余单位交 AI |

主游戏的政治叙事仍可聚焦 CNT-FAI，但战争地图的操作主体是阵营指挥部。政治身份与战场操作身份必须在界面标题中明确区分，避免“CNT 为什么能直接调动所有共和军”的叙事错位。

### 2.2 每月核心循环

```text
政治/事件阶段
  -> 军援、生产、征募来源结算到具体实体池
  -> 玩家从某个实体池组建或补充该实体的地图单位
  -> 地图行动与战斗
  -> 战损、缴获、撤编和资产转移结算
  -> 根据军事实力分布、资源分配和事件更新联盟凝聚力
  -> 检查战争胜负、整编节点和内部危机
```

核心循环中的关键选择不是“某支友军是否听令”，而是“有限的人力和重装备交给谁、是否集中到国家军队、由此换来怎样的战争效率与政治后果”。

### 2.3 与游戏定位和玩家体验的匹配

《自由未烬》的主体是政治组织与历史路线模拟，而不是师级作战沙盘。军事系统因此承担“把多年政治选择兑现为战争条件”的职责，不能反过来吞噬政治主循环。

| 设计目标 | 本方案的对应机制 | 体验判断 |
|---|---|---|
| CNT-FAI 视角但战时代表联合国家 | 政治叙事身份与地图指挥身份分离，阵营内纯全指挥 | 玩家不会因多党派设定失去基本操作权 |
| 战前军备与组织工作有后果 | 来源实体池、准备阈值、地方可达系数 | 准备有价值，但历史驻防基本盘阻止五年积累直接锁死战局 |
| 共和国的内部矛盾可玩且可理解 | 资产归属、军械分配、人民军化和凝聚力月结 | 冲突来自可见选择，不依赖隐藏抗命骰或抽象授权 |
| 两场战争共享学习成本 | 同一资产、战斗、补充与账本引擎，不同 `WarDefinition` | 1934 是短战役教学，1936 扩展为长期战略战 |
| 历史路线与架空路线都成立 | 史实月份、组织存续条件、明确的高门槛三方化 | 历史结果可自然收敛，架空结果必须由连续政治选择支付代价 |
| 避免微观管理压过政治 | 池只保留三项资产，全局军事化只有三级 | 玩家管理的是组织与分配，不是逐枪逐车后勤表 |

因此，该设计与整体定位匹配，但成立的前提是战争 UI 始终围绕“来源、去向、政治后果”组织信息，并把单回合地图操作控制在少量高价值决策内。若后续继续增加弹药型号、军官忠诚、逐单位党派服从或更细装备门类，会破坏这一边界。

## 3. 数据模型

### 3.1 武装实体

引入独立于党派和地图阵营的 `ArmedEntity`：

```ts
interface ArmedEntity {
  id: ArmedEntityId;
  camp: MapFaction;
  politicalSponsor?: Party | 'CNT_FAI' | 'STATE' | 'FOREIGN';
  kind: 'state' | 'party_militia' | 'regional' | 'foreign_ground_force';
  status: 'inactive' | 'active' | 'integrated' | 'defeated';
  recruitmentRegions: string[];
  activeFrom?: { year: number; month: number };
  activeTo?: { year: number; month: number };
  successorId?: ArmedEntityId;
  pool: {
    manpower: number;
    artillery: number;
    tanks: number;
  };
}
```

`politicalSponsor` 只负责把军事份额映射到联盟政治，不拥有另一份库存。一个政党可以支持多个武装实体，一个武装实体也可以在整编后更换继承者，但同一资产在任一时刻只能属于一个池或一支地图部队。

阵营公共经济、延期回收、战俘和在途援助不塞入武装池，而由战争状态单独保存：

```ts
interface CampWarEconomy {
  supplies: number;
  commandPoints: number;
  centralIndustrialReserve: number;
  recoveryQueue: RecoveryOrder[];
  prisoners: PrisonerRecord[];
  pendingAid: PendingAidShipment[];
}

interface RecoveryOrder {
  ownerCamp: MapFaction;
  targetEntityId?: ArmedEntityId;
  dueTurn: number;
  assets: { manpower: number; artillery: number; tanks: number };
  reason: 'battle_recovery' | 'defeat_capture' | 'delayed_redeployment';
}

interface PrisonerRecord {
  captorCamp: MapFaction;
  originCamp: MapFaction;
  manpower: number;
  recruitable: false;
}

interface PendingAidShipment {
  id: string;
  sourceCountry: string;
  recipientCamp?: MapFaction;
  recipientEntityId?: ArmedEntityId;
  status: 'scheduled' | 'suspended' | 'delivered' | 'cancelled';
  assets: { manpower: number; artillery: number; tanks: number };
  supplies: number;
}

interface WarState {
  definitionId: 'asturias_war' | 'spanish_civil_war';
  phase: 'setup' | 'active' | 'three_way' | 'resolved';
  turn: number;
  camps: Record<string, {
    status: 'active' | 'defeated' | 'victorious';
    capitalProvinceId: string;
    economy: CampWarEconomy;
  }>;
  entities: Record<ArmedEntityId, ArmedEntity>;
  militarization: RepublicMilitarizationState;
  splitResolved: boolean;
  assetLedger: WarAssetTransaction[];
}
```

省份的 `industry` 是属地生产能力，始终从地图实时汇总；`centralIndustrialReserve` 只表示已脱离具体省份、可用于维修或生产队列的中央投入。二者不得互相复制。战俘只进入统计和后续事件，不属于可征募人员。

地图阵营枚举新增 `REVOLUTIONARY_COUNCIL`。它只在五月决裂完成时激活；不得复用 `WORKERS_ALLIANCE`，因为后者专指 1934 年阿斯图里亚斯工人联盟，二者的时间、领土和胜利条件完全不同。

### 3.2 地图部队

当前 `ArmyComposition` 把步兵、炮兵人员和坦克人员相加为 `manpower`，与新池的“人员＋装备”语义冲突。新版应统一为：

```ts
interface Army {
  entityId: ArmedEntityId;
  faction: MapFaction;
  serviceType?: 'army' | 'assault_guard' | 'civil_guard' | 'militia' | 'international' | 'regional';
  provinceId: string;
  manpower: number;       // 全部人员，不再与装备数量相加
  artillery: number;      // 标准化火炮强度点或炮兵连单位
  tanks: number;          // 车辆数或标准化装甲强度点
  maxManpower: number;
  maxArtillery: number;
  maxTanks: number;
  morale: number;
  combatReadiness: number;      // 训练、经验、干部和战术效率，0-100
}
```

`entityId` 表示资产从哪个池支出，`serviceType` 表示这支地图部队按哪一种战术模板作战。因此，突击卫队仍可拥有较高城市战与治安修正，国民警卫部队仍可拥有守备特征，但二者与正规军从同一个国家武装池补员。

当前代码的 `militarization: 0–100` 实际被当作战斗效率倍率，迁移时应改名为 `combatReadiness`。新的军事化等级属于共和国阵营全局状态，不能放在每支部队或每个党派池中重复保存；战斗结算只从全局状态派生一次阶段修正。二者分离后，“训练得好但仍处于自治纵队阶段”和“训练一般但已经进入混合旅过渡”可以同时成立。战斗公式也不能继续把一辆坦克等同于一名人员。

### 3.3 共和国军事化状态

```ts
interface RepublicMilitarizationState {
  level: 0 | 1 | 2;
  stage: 'autonomous_columns' | 'mixed_brigade_transition' | 'popular_army';
  advancedAt?: { year: number; month: number };
  l2Decision?: 'pending' | 'accepted' | 'refused';
}

interface MilitarizationModifiers {
  combatPowerMultiplier: number;
  moraleModifier: number;
  casualtyMultiplier: number;
}

const REPUBLIC_MILITARIZATION_MODIFIERS: Record<0 | 1 | 2, MilitarizationModifiers> = {
  0: { combatPowerMultiplier: 1.00, moraleModifier: 0, casualtyMultiplier: 1.00 },
  1: { combatPowerMultiplier: 1.05, moraleModifier: 5, casualtyMultiplier: 0.95 },
  2: { combatPowerMultiplier: 1.10, moraleModifier: 10, casualtyMultiplier: 0.90 },
};
```

该状态只有一份。任何升级都同时改变共和国境内全部党派民兵的制度阶段；不能出现 CNT 为 L1、UGT 为 L0、PCE 为 L2 的并行等级。`advancedAt` 用于历史事件、存档迁移和冷却检查，`l2Decision` 防止同一不可逆选择反复弹出；二者都不是政治授权或服从度。

`MilitarizationModifiers` 不进入存档，而由 `level` 查表得到。战斗中按以下顺序且只应用一次：

```text
阶段有效士气 = clamp(单位士气 + moraleModifier, 0, 100)
阶段战斗力 = 基础战斗力 × combatPowerMultiplier
阶段伤亡 = floor(原始伤亡 × casualtyMultiplier)
```

“全部共和国部队”包括国家军、突击卫队、国民共和国卫队、各党派民兵、自治武装和国际纵队，只要结算时仍属于共和国阵营。L0/L1 修正不改变任何单位的 `entityId`、资产所有权或池余额；L2 的原子转隶完成后统一改为 `republic_state_arms`。第三阵营成立后不再继承共和国军事化修正。

该数值档刻意克制。以单位士气 70 为例，L1 的战斗力与有效士气合计约提高 8.1%，L2 约提高 16.5%，再分别获得 5% 与 10% 的伤亡控制。它足以让整编成为重要战略收益，但不应压过兵力、重装备、地形和补给差距。士气加成只用于本次战斗的有效值并在 100 封顶，不永久治疗单位士气。

### 3.4 资产守恒

任一实体、任一资产类型都必须满足：

```text
期初池 + 本期流入
= 期末池 + 前线现存 + 本期永久损失 + 转给其他实体的净额
```

建立单位是“池 -> 前线”，不是凭空生成；战斗损失发生在已经部署的单位中，不得再次从池中重复扣除。

### 3.5 交易记录

池本身仍只有三项数值，但每次变化记录一条轻量战报：

```ts
interface WarAssetTransaction {
  date: { year: number; month: number };
  source: 'mobilization' | 'state_production' | 'private_aid' | 'foreign_aid'
    | 'capture' | 'integration' | 'disband' | 'combat_loss'
    | 'combat_recovery' | 'defeat_settlement' | 'legacy_migration';
  fromEntityId?: ArmedEntityId;
  toEntityId?: ArmedEntityId;
  manpower: number;
  artillery: number;
  tanks: number;
}
```

它用于解释“这批装备为什么属于该实体”，不是第四种库存。

### 3.6 战前准备状态

训练、地区网络和动员效率不是库存，单独保存为只影响开战转换的准备状态：

```ts
interface EntityPreparation {
  entityId: ArmedEntityId;
  readinessBonus: number;       // 0-20，只加到新生成骨干部队
  mobilizationModifier: number; // 0.50-1.50
  regionalAccess: string[];
  capabilities?: string[];      // 研发与编制解锁，不保存资产数量
}
```

该对象不能存人员、火炮或坦克，也不能在战争开始后继续提供月度资产。战前卡牌必须二选一：直接向来源实体池增加三项资产之一，或修改 `EntityPreparation`；不得同时增加抽象民兵数、通用军备和战争库存。战争开始后，组织卡产生的新志愿者直接进入对应实体池，训练卡只修改具体地图部队的 `combatReadiness`。

### 3.7 组织生命周期与武装实体门控

组织和武装实体是两个不同层级。组织回答“谁已经形成可持续的组织结构”，武装实体回答“谁实际拥有可部署人员和重装备”。采用以下状态：

```ts
type OrganizationStatus = 'unformed' | 'active' | 'dissolved' | 'suppressed';
type OrganizationUiVisibility = 'visible' | 'internal';

interface OrganizationDefinition {
  id: OrganizationId;
  owner: Party | 'CNT_FAI' | 'STATE' | 'FOREIGN';
  type: 'union' | 'political' | 'youth' | 'women' | 'agricultural'
    | 'militia' | 'command';
  uiVisibility: OrganizationUiVisibility;
  prerequisiteIds?: OrganizationId[];
  armedEntityId?: ArmedEntityId;
  historicalActiveFrom?: { year: number; month?: number };
  historicalActiveTo?: { year: number; month?: number };
}

interface OrganizationState {
  status: OrganizationStatus;
  establishedAt?: { year: number; month: number };
  endedAt?: { year: number; month: number };
  endReason?: 'integration' | 'dissolution' | 'suppression' | 'defeat';
}
```

运行时必须满足：

```text
激活民兵武装实体
= 对应组织 status == active
+ 全部 prerequisiteIds status == active
+ 当前战争/地区/日期条件成立
+ 通过统一 activateArmedEntityFromOrganization() 事务
```

- `active` 只表示组织存在，不赠送人员、火炮或坦克；资产仍由历史开局、征募、生产、援助和缴获逐项注入。
- `dissolved` 与 `suppressed` 都禁止继续征募。前者通常把资产转给继承实体，后者按事件决定扣押、地下化或损失，不能自动复制资产。
- `uiVisibility: 'internal'` 的非 CNT 组织不得进入组织面板、卡牌目标列表、提示框、月结组织列表或任何其他游戏 UI。历史事件正文可以提及其名称，但不能把内部组织状态暴露为可操作条目。
- 只有 `CNT_FAI` 所有、且明确标为 `visible` 的组织进入现有组织 UI。`Milicias Confederales` 在成立前不得显示占位槽，成立后才出现。
- 事件 `meta` 不参与组织成立判定。历史成立、解散和镇压都必须写入 `organizations[id].status` 及日期；场景开局直接水合该历史快照，不补放已经发生过的成立事件。

## 4. 建池资格与初始实体

### 4.1 建池资格

共和国阵营首先按所有权划成三类池：

1. **共和国国家武装池**：正规军、突击卫队、国民警卫队/国民共和国卫队，以及后续共和国人民军共用；这些名称是地图单位的兵种或历史编制，不是四份库存。
2. **党派民兵池**：CNT-FAI、PSOE/UGT、PCE 的 MAOC/第五团、POUM 等各一池；只有实际建立武装的党派才启用。
3. **特殊公共或外国武装池**：自治政府军与国际纵队不伪装成某党私兵；是否独立建池取决于其是否有独立征募、军援和编制来源。

党派或特殊武装至少满足以下三项中的两项才单独建池：

1. 有独立征募或成员网络；
2. 有独立军械、军援或后勤来源；
3. 能以自己的番号和干部体系组成地图部队。

只存在于议会、宣传或思想层面的政党不建池。规模过小、无法独立形成地图单位的武装团体，作为某个历史上更大的联合实体的修正项，不制造几十个微型池。

### 4.2 1934 年阿斯图里亚斯

|---|---|---|---|

## 5. 来源决定归属

### 5.1 固定归属表

| 来源 | 初始归属 | 历史理由与后果 |
|---|---|---|
| 工会会费、党派募捐、秘密采购 | 对应实际武装实体 | 属于组织自身掌握的兵刃 |
| CNT 工场和加泰罗尼亚改装车间 | CNT-FAI 实体 | 更适合产出少量装甲车/坦克点和火炮维修，而非完整坦克工业 |
| 共和国国家工厂与军械库 | 共和国国家武装池 | 之后可由国家分配给其他实体 |
| 苏联、墨西哥及共和国正式采购 | 共和国国家武装池 | 苏援提高 PCE 政治影响，但不自动成为 PCE 私有库存 |
| 共产国际直接组织的国际纵队人员 | 国际纵队 | 其国家配发装备可在国家池与国际纵队间明确转移 |
| 地方兵营或军械库被夺取 | 实际夺取者 | 联合夺取时由事件给出明确分配比例 |
| 战场缴获 | 完成占领的地图部队所属实体 | 允许中央征收一定比例，但必须显示转移及政治后果 |
| 德意官方军援 | 国民军国家军队或指定外国实体 | 不直接进入长枪党/卡洛斯派池 |
| 卡洛斯派地方网络与宗教募捐 | Requeté | 强化其独立军事份额与统一法令中的谈判地位 |
| 长枪党动员与地方夺械 | 长枪党民兵 | 与国家军援严格分开 |

### 5.2 国家分配

国家生产和正式外援先进入共和国国家武装池，而非无主总库。玩家可以通过“军械分配”行动把火炮和坦克转给某个民兵池：

- 资产所有权随转移改变；
- 接收方军事份额提高；
- 明显偏袒会降低联盟凝聚力；
- 向弱势战区的合理补给可降低失衡；
- 同一批资产不能同时算作国家军和党派民兵实力。

## 6. 战前积累如何进入战争

### 6.1 两部分开局

战争开局由两部分相加，但不得混为一笔：

1. **历史基本盘**：根据驻防、政变成败、兵营控制和地方动员事件生成固定的地图单位与基础预备池。
2. **玩家战前成果**：根据战前实际武装实体的人员、火炮、坦克和组织准备追加修正。

历史基本盘保证地图不会因玩家在 1931 年少点几次军备卡就完全失真；战前成果保证五年准备不是无效装饰。

### 6.2 转换流程

```text
确定战争与日期
  -> 水合该场景日期已存在的组织状态
  -> 按历史事件和组织前置激活本场战争民兵组织
  -> 由 active 民兵组织激活对应武装实体
  -> 依据事件链确定省份与驻防归属
  -> 生成历史骨干部队并赋予 entityId
  -> 把战前实体库存扣除已投入骨干部队的部分
  -> 计算剩余预备池
  -> 检查战前积累阈值，最多追加少量部队或质量修正
```

组织门控必须发生在地图部队生成之前。党派旗标、议席、支持率或旧 `armedForces.militias` 数字都不能绕过组织状态直接创建池；同样，组织 active 但战争动员事件尚未发生时，武装实体仍保持 inactive。

### 6.3 阈值而非线性爆兵

每个实体按自己的历史参考规模计算准备率：

```text
准备率 = 战前可动员资产 / 该实体的历史参考资产
```

首轮实现采用以下固定档位：

| 准备率 | 开战修正 |
|---|---|
| < 0.60 | 历史单位仍出现，但预备池不足、战斗训练度下降 |
| 0.60–0.99 | 历史基本盘，无额外单位 |
| 1.00–1.39 | 增加 1 支未满编骨干，或提高现有单位上限 |
| >= 1.40 | 再增加 1 支骨干；此后只增加预备池，不再无限增兵 |

火炮和坦克独立检查编制需求。人员达标但重装备不足时，只能生成轻装纵队；不能用多余人员凭空补出坦克。

### 6.4 开局资产不得重复计算

历史骨干部队必须从“战争开局注入总额”中扣除后再得到预备池。禁止同时把一批 CNT 民兵显示为地图上的三万人，又把同样三万人完整留在 CNT 池里。

### 6.5 旧军备—民兵字段接入规则

新存档不再把 `armaments`、`armedForces.militias.*` 或 `militiaCombatPower` 作为另一套战争库存。旧档首次载入 v3 时执行一次迁移：

| 旧字段 | 新归属 |
|---|---|
| `armedForces.militias.cntFai` | `MC` active 时等量进入 `cnt_fai_militias`；只有 `DC` active 时进入 `cnt_defense_committees`；两者都未成立时不建池，而按“旧人数/该实体历史参考人数”写入 CNT `mobilizationModifier`，限制在 `0.50–1.50` |
| 其他已有明确党派键的民兵人数 | 对应民兵组织和武装实体均 active 时等量进入该池；尚未成立时不建池，按同一准备率公式写入其 `mobilizationModifier` |
| `armaments` | CNT 前身或战时实体已经 active 时，每点折算为 `250` 名已具备轻武器的可动员人员并进入该池；没有合法 CNT 武装实体时，每点改为 `readinessBonus +1` 和 `mobilizationModifier +0.01`，分别受既有上限约束；迁移后旧值归零 |
| `militiaCombatPower` | `clamp(旧值, 0, 20)` 写入 CNT `readinessBonus`；迁移后不再参与战斗 |
| `hasArmoredCars = true` | 合法 CNT 武装实体 active 时增加 `2` 个坦克/装甲强度点；否则写入 `capabilities: ['armored_cars']`，待第一个合法 CNT 武装实体激活时兑现一次 |
| 地图阵营 `resources.manpower` | 进入该阵营国家武装池人员 |
| 地图阵营 `resources.tankReserve` | 进入该阵营国家武装池坦克 |

旧 `armaments` 的折算表示“已有武器足以把多少组织成员变成可部署武装人员”，不是凭空增加人口；迁移不能绕过组织门控提前成立任何民兵。迁移后的 CNT 总人员仍受该场战争历史参考规模和第 6.3 节骨干上限约束。新卡牌从此直接写入合法实体池或准备状态，不能继续生产旧字段。

## 7. 战时征募、补充、整编与战损

### 7.1 征募

玩家选择：省份、武装实体和编制。合法条件为：

- 省份由本阵营控制，并在该实体允许的征募区域内；
- 实体池拥有所需人员、火炮和坦克；
- 阵营拥有所需补给和工业能力；
- 新部队 `entityId` 等于出资实体。

省份每月产生的普通兵源统一进入国家军实体。党派民兵的人力增长来自组织卡、工会网络、地区委员会、难民或志愿者事件，不能让每个党派池同时吃一遍同一省人口。

### 7.2 补充

部队只能从自己的实体池获得人员和重装备。补充同时消耗阵营补给，火炮和坦克维修可额外消耗工业能力。

### 7.3 合并、拆分与整编

- 同实体部队可以直接合并；合并后保持该实体身份。
- 不同实体部队不能用普通“合并”吞掉身份。
- 跨实体合并必须走“整编/转隶”，先明确资产转移，再生成目标实体部队。
- 拆分部队继承原实体身份。
- **训练/正规化**：提高 `combatReadiness`，表示纪律、干部、战术与装备使用效率；不推进制度整编等级，也不改变资产归属。
- **L0 自治纵队**：各党派民兵池独立保有人员、火炮、坦克，所属地图部队沿用党派番号；玩家仍对共和国全阵营实行纯全指挥。
- **L1 混合旅过渡**：共和国全局进入统一编制、标准补给和联合参谋体系，并启用 L1 固定战斗力、有效士气与伤亡控制修正；所有党派池仍分开记录并独立补充，地图部队仍保留原 `entityId`，不发生资产转移。
- **L2 共和国人民军**：一次性汇总共和国阵营全部党派民兵、地区武装和国际纵队池及其地图部队，将人员、火炮、坦克逐项转入共和国国家武装池；全部相关部队的 `entityId` 改为 `republic_state_arms`，原独立池关闭，UI 只保留一个人民军槽位。`serviceType` 与账本来源仍可显示其历史名称，但不再代表独立资产所有权。
- L0 -> L1 只改变制度规则；L1 -> L2 必须调用统一的批量转隶函数，并为每个来源池、每项资产生成交易记录。
- 两次升级都由一次性事件链推进。军事事务卡只能训练、征募和调整现有部队，不能改变 `RepublicMilitarizationState.level`。
- L0 -> L1 是共和国战争制度的强制过渡，事件结算后直接进入 L1；组织抵触体现在凝聚力和文本，不允许某一党派单独停留 L0。
- L1 -> L2 事件必须提供“接受人民军化”与“拒绝最终统一”两个实质选项。接受设置 `level = 2`、`l2Decision = 'accepted'`，执行原子转隶，凝聚力 `-5`、革命热情 `-10`；拒绝保持 `level = 1`、设置 `l2Decision = 'refused'`，凝聚力 `-8`、革命热情 `+5`，并记录持续 `6` 个月的 `militarization_refusal` 危机原因。

历史上的军事化并非所有组织在同一日同步完成；这里采用全局等级是玩法抽象，表示共和国制度的总体状态。具体事件文本仍应表现第五团主动解散、无政府主义纵队抵触、中央政府施压等不同历程，不能把全局事件写成各派毫无分歧地同时改旗易帜。

### 7.4 战损与回收

- 战斗损失直接减少前线部队的人员、火炮和坦克，不再重复扣池。
- 正常撤退后，可将少量伤员与可修复装备排入原实体的延迟回收队列。
- 被包围歼灭时，回收率显著降低；部分火炮和坦克可被占领者缴获。
- 主动解散固定返还 `90%` 人员、`75%` 火炮和`75%` 坦克；三项分别向下取整，余量记为永久损失。
- 缴获进入完成占领的部队所属实体。若国家实行集中征收，可将一部分转入国家军并结算凝聚力。

这一流程保证池、前线和损失三者守恒，也使“缴获兵营”“丢弃重装备撤退”等历史事件具有真实价值。

## 8. 两场战争使用同一引擎、不同参数

### 8.1 通用 `WarDefinition`

```ts
interface WarDefinition {
  id: 'asturias_war' | 'spanish_civil_war';
  turnScale: 'days' | 'weeks' | 'months';
  daysPerTurn?: number;
  turnLimit?: number;
  playerFaction: MapFaction;
  activeFactions: MapFaction[];
  participatingEntities: ArmedEntityId[];
  mapScope: 'asturias_operations' | 'spain';
  baseCommandPoints: number;
  setupStrategy: 'historical_snapshot_plus_modifiers';
  victoryRules: VictoryRule[];
  internalCrisisRules: InternalCrisisRule[];
}
```

共用的是实体池、征募、补充、战损、缴获、AI 成本和战报；不同的是时间尺度、参战实体、胜利条件、地图范围和内部危机。

| 参数 | 阿斯图里亚斯战争 | 西班牙内战 |
|---|---|---|
| 回合 | `3` 天 | `1` 月 |
| 回合上限 | `5` | 无固定上限，以阵营败亡结束 |
| 基础指挥点 | 每方 `2` | 每方 `2` |
| 地图范围 | 五个局部目标节点 | 西班牙全国省份地图及受事件控制的海外通道 |
| 玩家初始阵营 | `WORKERS_ALLIANCE` | `REPUBLICAN` |
| 内部危机 | 无；UHP 只统一指挥 | 共和国军事化、五月危机、国民军统一法令 |

### 8.2 阿斯图里亚斯起义

历史上起义集中在 1934 年 10 月并在约两周内被镇压，不应要求工人军攻占马德里、马拉加、萨拉戈萨和瓦伦西亚。

固定规则：

- 工人联盟参战实体固定为社会主义矿工武装、CNT 地方武装和共产主义武装三个独立池；玩家作为工人联盟革命委员会对三者实行全指挥。
- 镇压方正规军、突击卫队、国民警卫与调入的非洲军地图部队都从共和国国家武装池支出和补充，仅以 `serviceType` 区分战术性质。
- 使用 `5` 个短回合，每回合代表 `3` 天；整场战争占用 1934 年 10 月的独立战役时钟，不额外推进主时间线月份。
- 地图目标集中在阿斯图里亚斯矿区、奥维耶多、特鲁维亚军工设施及通往莱昂的入口。
- 工人联盟的主要目标是控制矿区、夺取军械设施、孤立奥维耶多守军并坚持到全国声援窗口。
- 共和国镇压方目标是打通入口、夺回奥维耶多与矿区，并摧毁工人联盟有组织部队。
- 架空胜利不是“征服西班牙”，而是迫使政府谈判、触发全国总罢工扩散，或建立暂时存续的工人自治政权。
- 战前全国 CNT 军备不能 100% 瞬移到阿斯图里亚斯；必须乘以地方组织、运输通道和参与决定形成的地域可达系数。
- 阿斯图里亚斯战役在 5 回合内独立结算后回到主时间线，任何结果都不直接禁用 1936 年内战；其结局通过囚犯、流亡干部、组织声望和国家镇压四类持久标记影响后续事件。战役地图部队不会原样保留到 1936 年，幸存人员按结局事件明确转为地下干部、囚犯或复员者，火炮和坦克则按战役结束时的实际控制者缴获，禁止整支部队跨两年冻结保存。

局部目标层固定包含 `西部矿区`、`东部矿区`、`奥维耶多`、`特鲁维亚军工设施`、`莱昂通道` 五个目标；它们映射到地图省份或同一省份内的战役节点，不要求修改全国省份粒度。回合结束时按下表累计胜利点：

| 条件 | 工人联盟 VP | 镇压方 VP |
|---|---:|---:|
| 控制西部矿区 | `+1/回合` | `+1/回合` |
| 控制东部矿区 | `+1/回合` | `+1/回合` |
| 控制奥维耶多 | `+2/回合` | `+2/回合` |
| 控制特鲁维亚 | `+1/回合` | `+1/回合` |
| 控制莱昂通道 | `+1/回合` | `+1/回合` |

胜负按以下顺序结算：

1. 任一方有组织前线人员降至开局值的 `20%` 以下，立即判该方军事崩溃。
2. 第 5 回合结束时，工人联盟若同时控制两处矿区、奥维耶多和特鲁维亚，则取得“革命胜利”。
3. 未满足上项，但工人联盟 VP `>=18` 且仍保有至少 `35%` 开局有组织人员，则取得“迫使谈判”。
4. 其余结果为共和国镇压胜利；工人联盟 VP `>=12` 时标记为“顽强抵抗”，影响囚犯、流亡者和 1936 年组织记忆，但不改写胜者。

全国组织输送到阿斯图里亚斯的地域可达系数固定为：基础 `10%`，UHP 已建立 `+10%`，阿斯图里亚斯 CNT 地方组织准备充分 `+10%`，莱昂通道未受政府封锁 `+10%`，总值限制在 `10%–40%`。只对战前 CNT 池可调用资产计算一次；社会主义矿工和共产主义地方武装使用各自当地来源，不重复读取全国 CNT 库。

### 8.3 1936 年内战

- 开局仍由 7 月政变事件链决定各省与驻军归属。
- 马德里、巴塞罗那、塞维利亚、萨拉戈萨、奥维耶多、海军和非洲军团的选择直接生成相应实体部队及军械归属。
- 战前民兵积累只追加少量骨干、预备池与质量，不把历史驻防改造成自由布阵。
- 国际纵队在 1936 年秋后出现；人民军和混合旅在 1936 年秋开始形成；第五团在 1937 年初转入人民军。
- 胜负采用首都、战略价值与军事实体存续的组合，不能仅靠吞并大量无防低价值省滚雪球。

全国内战以 `1` 个主时间线月份为一个战略回合。每回合顺序固定为“月初生产与事件 -> 玩家阵营行动 -> 各 AI 阵营行动 -> 补给、回收与凝聚力月结 -> 败亡与危机检查”。每个活跃阵营基础获得 `2` 点指挥点；事件、建筑和难度只能在独立字段上增减该回合额度，不能改变命令的政治合法性。

## 9. 共和国阵营政治与五月事件

### 9.1 唯一政治约束：联盟凝聚力

沿用现有 `CoalitionState.cohesion`，不新增部队服从值。它表示共和国政治联盟能否继续共同作战。

每月变化固定为：

```text
下月凝聚力
= 本月凝聚力
+ clamp(共同战果 + 公平分配 - 份额失衡 - 分配偏袒 - 异常伤亡, -3, +2)
+ 历史事件修正
```

具体判定如下：

| 月结项目 | 数值 | 判定 |
|---|---:|---|
| 共同战果 | `+1` | 本月夺取一个敌方 `strategicValue >= 7` 的省份，或成功守住一个遭攻击的本方同级省份 |
| 公平分配 | `+1` | 本月中央重装备转移覆盖至少两个政治集团，且任一集团所得不超过转移总量的 `60%` |
| 份额失衡 | `0/-1/-2/-3` | 总失衡分别为 `<15`、`15–29.99`、`30–44.99`、`>=45` |
| 分配偏袒 | `-1` | 单一集团取得本月中央火炮与坦克战力点的 `>60%`，且其月初军事份额已 `>=35%` |
| 异常伤亡 | `-1` | 某集团本月人员伤亡占全阵营 `>50%`，且其月初军事份额 `<35%` |

单月结构性扣分合计最低为 `-3`，结构性奖励最高为 `+2`；重大历史事件在结构结算后另行加减，可以突破该范围。凝聚力始终限制在 `0–100`。界面必须列出本月每一项原因，避免凝聚力成为不可解释的倒计时。

### 9.2 军事份额

武装实体映射到其政治集团后计算：

```text
实体战力点 = 人员 / 1000 + 火炮 × 0.35 + 坦克 × 0.60
军事份额 = 该集团全部池内与前线战力点 / 全阵营战力点 × 100
政治话语权 = 联盟贡献度 × 40% + 内阁席位份额 × 25%
             + 所控战略点份额 × 20% + 支持率份额 × 15%
失衡 = 各集团 |军事份额 - 政治话语权| 的总和
```

四项政治话语权输入都先在当前联盟成员间归一化为 `0–100`；没有有效分母的项记为各成员均分。该权重只用于阵营政治，不改变地图命令是否合法。火炮和坦克权重与战斗公式使用同一常量，禁止政治层另设一套兑换率。

### 9.3 五月事件的历史结构

危机预警阈值为凝聚力 `<=40`，事件资格阈值为 `<=25`。历史模式的主要锚点是 1937 年 5 月巴塞罗那电话局冲突，触发条件固定为：

- 西班牙内战进行中；
- 加泰罗尼亚仍在共和国阵营且 CNT/委员会拥有显著地区控制；
- 联盟凝聚力 `<=25`；
- 最近 `6` 个月内至少发生过一次中央集权、明显军械偏袒、强制整编或治安冲突；
- Historical 模式在 1937 年 5 月检查；其他模式使用条件驱动，并设置不早于 1936 年秋的合理窗口。

Historical 模式只在 1937 年 5 月进行一次检查；条件不满足则不强制制造冲突。其他模式从 1936 年 10 月起每月检查，但同一危机链只能进入一次。`date` 只服务 Historical 调度；非历史难度必须由真实状态字段和 `condition` 触发，不能读取事件 `meta`。

危机分三步：

1. **电话局冲突**：地方治安力量与 CNT 控制设施发生交火，暂时冻结加泰罗尼亚的部分补给和工业收入。
2. **政治选择**：调停、接受中央接管、或组织抵抗。
3. **全国决裂结算**：若选择组织抵抗，立即建立第三阵营并进入全国三方战争；不先进行巴塞罗那 1–2 个特殊短回合。

### 9.4 三种结局

| 选择 | 历史/架空性质 | 结果 |
|---|---|---|
| 调停妥协 | 可行的温和架空线 | 凝聚力 `+10`；加泰罗尼亚中央补给与工业冻结 `1` 个战争回合；CNT 让出公共秩序武装控制，POUM 保持现状；危机在 `6` 个月内不重复触发 |
| 接受整编与中央接管 | 历史收敛线 | 若仍为 L1，则完成全部党派池的 L2 人民军化；若已为 L2，则不再转移资产。凝聚力 `+8`、革命热情 `-10`；POUM 转为非法并进入镇压事件链 |
| 武装抵抗 | 高度架空升级线 | 立即成立第三阵营并把内战升级为全国三方战争；按既定规则一次性结算实体、部队和省份归属 |

“直接全国化”指跳过巴塞罗那局部战的前置检定，并不等于凭空生成部队。由于历史上的五月事件主要是加泰罗尼亚内部冲突，这条全国三方战争路线必须明确标注为高度架空分支。

第三阵营初始领土采用以下确定规则：

```text
第三阵营初始省份
= 加泰罗尼亚、阿拉贡、瓦伦西亚三区内：
   当前属于共和国，且没有任何非 CNT 部队驻扎的省份
+ 全地图：当前仅由 CNT 部队实际占有的其他省份
```

三区使用固定省份 ID 白名单：加泰罗尼亚为 `barcelona/gerona/lerida/tarragona`，阿拉贡为 `zaragoza/huesca/teruel`，瓦伦西亚为 `valencia/alicante/castellon`。`balears`、`murcia` 和 `andorra` 不在三区白名单内，即使旧地图分组曾把它们归入相近文化区；它们只能按“全地图由 CNT 单独实际占有”规则转入。

- 国民军占领的省份不因位于三区而自动转移。
- 三区内空置的共和国省份，只要没有非 CNT 部队驻扎，就转入第三阵营。
- 三区内只驻有 CNT 部队的共和国省份转入第三阵营。
- 三区内存在任何非 CNT 部队的省份继续属于共和国，即使同时存在 CNT 部队。
- 三区外只有在 CNT 部队构成实际占有力量时才转入，不按党派支持率或历史想象扩张版图。

混合驻军按“有序分离”处理：

1. 先按上述规则确定第三阵营初始省份，混合驻军省份保持共和国所有权；
2. 再把这些省份中的 CNT 部队转为第三阵营，并沿地图邻接关系撤往距离最近且可达的第三阵营省份；
3. 距离相同时优先选择补给条件较好的省份，不由玩家在事件结算中瞬移选点；
4. 若不存在可达省份，该部队进入延迟重部署队列，暂时从地图移除；人员、火炮、坦克仍逐项归 CNT 池，只结算撤离损耗；
5. 撤离损耗固定为人员 `5%`、火炮 `10%`、坦克 `10%`，逐项向下取整后从原部队扣除并写入永久损失记录，不转化为共和国缴获。

有序分离不触发额外局部战，也不改变“该省留在共和国”的判定。第三阵营第一个正常回合开始前必须完成全部撤离或延迟重部署结算，地图上不得留下敌对阵营同省共存状态。

### 9.5 决裂时资产归属

- CNT 民兵池的人员、火炮、坦克及其所属地图部队整体转入第三阵营，不逐支随机判定。
- POUM 只有在已经成立、组织仍合法、尚未遭镇压且 `partyRelations.POUM >= 70` 时，才将整个民兵池及所属部队加入第三阵营；四个条件任一不满足即整体留在共和国。
- UGT/PSOE 与 PCE 民兵池及其所属部队整体留在共和国，不进行随机、逐单位或按地区拆分。
- 共和国国家武装池原则上完整留在共和国；其中的人民军、突击卫队和国民共和国卫队地图单位不因标签不同被拆池。
- 加泰罗尼亚公共秩序武装按事件结果归共和国或革命委员会。
- 跨实体混编部队必须在整编时已完成资产转移；不能到决裂时再猜测其中各党派比例。
- 在 L1 的五月危机中接受中央整编，必须执行与正常 L2 事件相同的全量原子转隶，不允许只转移 CNT 或只转移一部分资产；选择调停或武装抵抗则保持各池独立。

领土快照先于 POUM 站队结算，且仍只以 CNT 驻军判断省份是否转入第三阵营。POUM 加入不会额外改色；其位于共和国保留省份的部队按与 CNT 相同的有序分离规则撤出。

关系 70 是高门槛而非自动站队。当前项目中 POUM 初始关系为 50；从 1931/1933 路线选择“欢迎 POUM 成立”后为 65，仍需至少一次后续合作；1936 直开局则需要累计提高至少 20 点关系。“跨党派关系”“国际联系”“选择我们的敌人”等行动共同提供该路径。本方案将党派关系统一规范为 `-100～100`，所有旧的 `0～100` 截断写入点必须迁移到同一帮助函数。

历史上 POUM 在 1937 年五月冲突中与 CNT 基层站在同一侧，因此 70 门槛会让游戏中的 POUM 参战率低于纯历史推演。这里将其解释为“愿意把整个独立军事组织投入全国性反中央战争”的门槛，而不是“是否同情 CNT”的门槛：关系不足时 POUM 整池留在共和国阵营，不等于其政治上支持 PCE 或中央镇压。

若共和国已经达到 L2，党派池与 CNT 单位身份均已被消除，五月危机仍可作为政府改组、镇压和联盟政治事件发生，但不得再提供“组织武装抵抗”选项，也不得按支持率重新生成 CNT 或 POUM 军队。只有此前拒绝 L2、仍停留在 L1 时，才保留全国三方战争路线。

### 9.6 决裂时公共资源与外援

第三阵营资源结算采用“属地继承＋中央储备比例分割”，并与领土、武装池转移处于同一个原子事务中：

```text
第三阵营战略点 = Σ 分裂后由第三阵营控制城市的 strategicValue
共和国战略点 = Σ 分裂后由共和国控制城市的 strategicValue
第三阵营中央储备份额 = 第三阵营战略点 /（第三阵营战略点 + 共和国战略点）
共和国中央储备份额 = 1 - 第三阵营中央储备份额
```

- 战略点统计在第三阵营领土快照和混合驻军省份归属判定完成后、任何中央储备转移前进行，只结算一次。
- 统计范围仅限分裂前属于共和国阵营、分裂后分别由共和国或第三阵营控制的城市/省份。国民军在分裂前已经占领的地区不进入双方分母。
- 直接读取现有地图省份的 `strategicValue`，不另设“城市价值”副本；项目中每个地图省份都可作为一个城市/地区结算单位。
- 如果双方战略点之和为 0，则第三阵营中央储备份额记为 0，全部中央储备留给共和国，避免除零和凭空分配。
- 省份本地补给、地方库存和工业产能随省份所有权直接转移，不得再次计入共和国中央储备，否则会双重分割。
- 先冻结分裂前共和国中央 `supplies` 与可转移工业储备快照，再逐项按分割率计算第三阵营所得；所有离散资源向下取整给第三阵营，余数留共和国。
- `industrialCapacity` 中由当前省份实时汇总的部分只按领土重算；只有确实独立保存的中央工业储备、维修额度或生产队列投入才参与比例分割。
- 人员、火炮、坦克继续按武装实体归属转移，不再受上述分割率二次切分。
- 已抵达并完成归属的外援资产随其当前武装实体转移；尚在运输或生产队列中的苏联、墨西哥及其他外国援助全部暂停，由后续外交事件重新指定共和国、第三阵营、分批拆分或取消。
- 分割结束后写入一组可审计交易记录，并验证共和国与第三阵营所得之和严格等于分裂前快照。

战略点分割把中央储备继承直接绑定到分裂瞬间的地图实力，而不是战前党派扩军或抽象人口权重。它会奖励对巴塞罗那、瓦伦西亚、萨拉戈萨等高价值节点的实际控制，同时避免把同一块地方工业既作为属地产出、又作为中央库存重复转移。分割率严格使用 `0%–100%` 的原始比例，不设上下限；三方始终互相开战，也不设置停火或重整保护窗口。

### 9.7 全国三方化原子事务

只有 `militarization.level === 1`、`l2Decision === 'refused'`、五月危机正在结算、按领土规则至少能形成一个第三阵营省份且玩家选择“武装抵抗”时可以调用 `resolveMaySplit`。没有合法初始省份时该选项显示为不可执行，不能建立无领土阵营。函数按以下顺序执行，任一守恒断言失败则整笔回滚：

1. 冻结省份、驻军、各实体池、共和国中央补给、中央工业储备和在途外援快照。
2. 仅以 CNT 驻军和三区规则计算领土集合；POUM 站队不参与领土判定。
3. 激活 `REVOLUTIONARY_COUNCIL`，把领土集合一次性改属第三阵营，本地工业与资源随地图所有权重算。若巴塞罗那在集合内，以巴塞罗那为首都；否则以集合内 `strategicValue` 最高的省份为临时首都，同值时依次按距巴塞罗那最短路径、字母序 ID 选定。
4. 将 CNT 整池与全部所属部队转入第三阵营；按四项条件决定 POUM 整池去留；UGT/PSOE、PCE 和共和国国家武装完整留在共和国。
5. 对共和国保留省份中的 CNT/已加入 POUM 部队执行最近可达撤离；无路径者进入有损延迟重部署。
6. 计算 `C / (C + R)`，按无上下限比例分割中央补给和中央工业储备；离散资源给第三阵营向下取整，余数留共和国。
7. 将所有未抵达外援置为 `suspended`，清空旧接收方，在后续外交事件中重判；已抵达援助只随当前实体走。
8. 将三组敌对关系同时设为双向战争：共和国—国民军、共和国—第三阵营、国民军—第三阵营。
9. 设置 `war.phase = 'three_way'`、`splitResolved = true`，重新建立共和国 AI，并把玩家控制范围切换到第三阵营。
10. 校验地图不存在敌对同省单位、三项资产无负数、中央储备总量守恒、每支部队只有一个实体且每个实体只有一个阵营，然后提交事务。

该事务不生成任何新部队或额外资产，也不修改已经属于国民军的省份。事件效果只能调用该领域函数，不能在事件文件里逐项复制上述逻辑。

## 10. 国民阵营内部派系

### 10.1 基本结构

国民阵营的政治集团至少包括：军方统帅集团、长枪党、卡洛斯派、阿方索派及右翼文官。只有拥有独立武装的军方、长枪党和卡洛斯派建立池；纯政治集团不建池。

国民阵营同样可以使用 `national_front.cohesion` 与“军事份额/政治话语权失衡”，但在当前玩家不控制国民军时由 AI 和历史事件管理。

### 10.2 历史节点

- 1936 年秋：佛朗哥取得最高军事与国家领导地位，军方国家实体权重上升。
- 1937 年 4 月：统一法令把长枪党与卡洛斯派政治组织强行合并为 FET y de las JONS。
- Hedilla 危机与卡洛斯派抵触体现为逮捕、边缘化、资产整编和凝聚力变化，而不是自动爆发另一场全国内战。
- 意大利 CTV 与德国秃鹰军团保持外国来源；前者是地面实体，后者是战区支援。

### 10.3 统一法令机制

统一法令结算三件事：

1. 政治赞助者合并，但不复制 Requeté 和长枪党库存；
2. 一部分民兵人员、火炮和坦克转入国民军国家实体，原池缩小；
3. 国民军正规化、补给效率和 AI 协同提高，但长枪党或卡洛斯派政治不满上升。

若佛朗哥权威低、战局恶化且国民阵营凝聚力极低，可出现“统一失败”架空支线：优先表现为动员下降、内部清洗或局部冲突。只有极端条件才允许地图分裂，避免把历史上被强制压服的矛盾夸大为常态三方战争。

## 11. 与其他系统的耦合

| 系统 | 耦合程度 | 输入军事系统 | 军事系统反向输出 | 主要风险 |
|---|---|---|---|---|
| 地图与战斗 | 极高、双向 | 省份、地形、工业、战斗结果、共和国军事化等级 | 单位、占领、缴获、战损 | 资产重复扣除、阶段修正重复应用、单位身份在合并时丢失 |
| 战前军备/组织 | 极高、单向转双向 | 实体人员和重装备来源 | 战损与整编改变组织实力 | 五年积累过强导致开局雪球 |
| 国家经济 | 高、双向 | 工业能力、补给、军费 | 战争消耗、控制区变化 | 实体池与阵营资源重复表示同一物资 |
| 外交与外援 | 高、定向 | 苏援、墨援、德援、意援、国际志愿者 | 外交关系和政治影响 | 把国家援助误记成某党私产 |
| 联盟/党派政治 | 高、低频 | 话语权、联盟成员、事件选择 | 军事份额、偏袒、伤亡负担、决裂 | 凝聚力形成不可逆负反馈 |
| 卡牌系统 | 中高 | 1 AP、冷却、条件和组织前置 | 具体池交易、整编和地区修正 | 文案成本与真实扣除不一致 |
| 事件系统 | 极高、离散 | 历史日期、条件、事件链 | 开战、军援、整编、决裂、投降 | 事件直接整块覆写地图，绕过守恒规则 |
| 地区自治/控制 | 中高 | 加泰、巴斯克、阿拉贡状态 | 征募范围、五月事件、分裂版图 | 政治控制与地图占领混成一个字段 |
| 结局系统 | 中 | 战争胜负、内部胜者 | 结局路线 | 旧结局优先级覆盖新结局 |
| AI、存档与 UI | 极高、工程性 | 相同规则源、字段归一化 | 可玩性和可解释性 | 玩家与 AI 使用两套成本；旧档丢实体身份 |

### 11.1 控制耦合强度

- 战斗只读取地图部队，不在每次攻击时读取党派关系。
- 共和国战斗额外读取一次全局军事化等级并转换为派生修正；不得把修正预写进单位后又在战斗中重复读取。
- 政治只在月结、军械分配、整编和重大事件时读取军事份额。
- 所有资产变化走统一领域函数，事件和卡牌不得直接重写整份 `armies` 或池对象。
- 地图资源负责“阵营能否保障作战”，实体池负责“谁拥有可投入的人与重装备”，两者职责不得互换。

耦合等级的工程含义固定为：**极高**表示必须共享同一原子事务和守恒测试；**高**表示通过稳定领域接口双向交换结果；**中高**表示在月结或事件节点读取快照；**中**表示只消费最终状态，不反向参与即时战斗。

唯一允许跨系统调用的军事领域入口为：

```text
setupWar(definitionId, historicalChoices)
changeEntityAssets(entityId, delta, source)
recruitArmy(entityId, provinceId, template)
reinforceArmy(armyId, requestedAssets)
transferEntityAssets(fromId, toId, assets, reason)
resolveBattle(attackerIds, targetProvinceId)
advanceRepublicMilitarization(targetLevel, decision)
resolveMaySplit()
resolveCampDefeat(campId)
```

地图系统拥有省份、邻接、地形、驻军位置和所有权；军事领域拥有实体池、部队资产、战斗与败亡事务；政治系统拥有党派、联盟凝聚力和事件选择；经济系统拥有地方产出和阵营公共资源。事件与卡牌只能向上述入口提交意图并接收结果，不能直接整块覆写 `provinces`、`armies`、实体池或凝聚力。这样保留必要的高耦合，同时阻止地图、政治、卡牌各自实现一套资产规则。

## 12. 卡牌与事件重定义

### 12.1 军事卡牌

**组织卡：防御委员会**

- `defense_committee_formation` 只把 `DC` 设为 active 并记录成立时间，不直接成立 `MC`，也不自动增加武装资产。
- “武装防御委员会”选项只在 `DC` active、`MC` unformed、战争尚未开始且资源充足时出现；其人员与重装备进入 `cnt_defense_committees`，不能提前写入 `cnt_fai_militias`。
- 1936 年战争动员事件成立 `MC` 时，统一转隶函数把 `cnt_defense_committees` 全池及准备状态转给 `cnt_fai_militias`，随后关闭前身实体。
- `MC` 不能通过组织卡提前购买，也不能仅因 CNT/FAI 支持率或民兵数达到阈值自动出现。
- 非 CNT 组织没有可见卡牌、按钮或组织槽；它们只由场景水合和历史事件维护。

**民兵整编**

- 扩充纵队：向指定实体池增加来源明确的人员，再从池中建立单位；不能直接在地图凭空加兵。
- 训练与正规化：消耗本民兵池与阵营补给，提高现有单位的 `combatReadiness`，保留党派归属且不提高军事化等级。
- 集中武器组建突击部队：从选定党派池支出人员、火炮和坦克，建立或改编对应地图部队；不得修改全局军事化等级。
- 删除卡牌中的“推进军事化”与“完成人民军化”选项，避免玩家用可重复卡绕过历史事件、日期条件和政治决断。

**无政府？坦克？！**

- 历史化为“加泰罗尼亚战争工业与装甲车辆计划”。
- 主要产出应是少量坦克点、装甲车抽象和火炮维修能力，而不是把 CNT 发展成大规模坦克工业。
- 研发失败损失工业/军备和时间，不应随机消灭一千名尚未上战场的民兵。

**阿拉贡前线**

- 招募来源为阿拉贡受控地区和集体化网络，进入 CNT-FAI 池。
- 整顿纪律影响地图上对应实体单位的 `combatReadiness`，而不是全局 `militiaCombatPower` 或制度军事化等级。
- 教会与地方政策继续影响阶级支持，并可改变地区征募效率和凝聚力。

首轮卡牌参数固定如下：

| 卡牌/选项 | AP 与冷却 | 新效果 |
|---|---|---|
| 组织：武装防御委员会 | `1 AP`，沿用组织卡 `6` 月冷却 | 消耗 `1` 资源，向 `cnt_defense_committees` 增加 `1000` 人员，三十人派不满 `+6`；要求 `DC` active、`MC` unformed、战争未开始 |
| 民兵整编：正规训练 | `1 AP`，冷却 `1` 月 | 消耗 `500` 阵营补给，使一支所选党派民兵单位 `combatReadiness +5`，上限 100 |
| 民兵整编：招募民兵 | 同上 | 在合法征募区消耗 `500` 补给，向所选党派池增加 `500` 人员 |
| 民兵整编：突击营 | 同上 | 从同一实体池调出 `1000` 人员及 `2` 火炮或 `1` 坦克，组建对应突击单位；不产生新资产 |
| 加泰装甲车辆计划：常规研发 | `1 AP`，冷却 `6` 月 | 消耗 `10` 中央工业储备，研发进度 `+25` |

| 军事政策 | 沿用现有 `1 AP` 与 `6` 月冷却 | 只改变共和国国家池的征募、生产或准备状态；不得直接改写党派池、地图部队或军事化等级 |

卡牌条件与预览必须显示目标实体、实际三项资产变化、补给/工业成本和冷却。若没有合法目标实体或余额不足，选项不可执行；不得退回旧 `armaments`、`militiaCombatPower` 或笼统“民兵 +X”的写法。

### 12.2 历史事件

- 快速开局与沉浸式开局最终调用同一个战争设置函数。
- 事件只提交“谁控制兵营、谁夺取军械、谁获得地区”的结果，由设置函数生成地图和池。
- Historical 模式使用准确月份；Normal/Easy/Hard/Sandbox 必须用显式条件，不依赖 `date` 自动触发。
- 所有选项中英双语、条件可见、结果可预览；实质选项设置正确冷却并使用现有派系帮助函数。
- L0 -> L1 由 1936 年 10 月的民兵军事化与混合旅制度事件推进；非历史模式最早同样为 1936 年 10 月，并必须满足内战进行中、共和国仍活跃且 L0 的真实状态条件。
- L1 -> L2 由 1937 年 2 月的人民军统一决断推进，与 L0 -> L1 至少间隔 `3` 个完整月；接受与拒绝必须设置持久决策字段，防止事件重复。
- 接受 L2 后，批量转隶与关闭武装抵抗是同一事件效果的一部分；拒绝 L2 后，保留所有党派池且不得发生任何隐性资产转移。

## 13. 战斗与地图需要同步修订的规则

### 13.1 战斗公式

当前战斗把人员、火炮和坦克放在同一人数尺度，并以随机骰乘整体战力。新版统一使用以下首轮平衡公式；所有系数集中在 `CombatRules`，卡牌和事件不得各自复制：

```text
人员战力 = manpower / 1000
火炮战力 = artillery × 0.35 × 火炮地形系数
装甲战力 = tanks × 0.60 × 装甲地形系数
基础战力 = 人员战力 + 火炮战力 + 装甲战力

训练系数 = 0.75 + 0.50 × combatReadiness / 100
有效士气 = clamp(morale + 军事化士气修正, 0, 100)
士气系数 = 0.75 + 0.50 × 有效士气 / 100
补给系数 = 0.70 + 0.30 × clamp(本回合需求满足率, 0, 1)

最终战力 = 基础战力
         × 训练系数
         × 士气系数
         × 补给系数
         × 共和国军事化战力系数
         × 防守地形与工事系数
         × 难度系数
         × 随机系数
```

地形与随机参数固定为：

| 参数 | 平原 | 城市 | 山地 | 森林 |
|---|---:|---:|---:|---:|
| 火炮地形系数 | `1.00` | `0.80` | `0.65` | `0.75` |
| 装甲地形系数 | `1.00` | `0.55` | `0.35` | `0.50` |
| 防守地形系数 | `1.00` | `1.20` | `1.30` | `1.15` |

每级工事再令防守方战力乘以 `1 + 0.10 × fortification`。随机系数在 `[0.90, 1.10]` 均匀取值，保证随机性会改变接近战，但不会翻转两倍以上的纯战力差。难度系数只作用于 AI：Easy `0.95`、Normal/Historical/Sandbox `1.00`、Hard `1.05`。

双方人员原始损失率分别计算：

```text
原始人员损失率 = clamp(0.06 × 敌方最终战力 / 本方最终战力, 0.02, 0.18)
训练伤亡系数 = 1.10 - 0.20 × combatReadiness / 100
最终人员损失 = floor(manpower × 原始人员损失率
                 × 训练伤亡系数 × 军事化伤亡系数)
```

火炮损失率等于本方人员最终损失率的 `0.75` 倍，坦克损失率等于 `0.60` 倍；战败撤退方再分别乘 `1.25` 和 `1.50`。无合法撤退路径时，人员额外损失 `10%`，剩余火炮和坦克各有 `30%` 被胜方缴获、其余随幸存部队进入延迟重部署。所有比例逐项向下取整，任何阶段都不得把重装备数量加进人员。

完整结算顺序固定为：

1. 校验阵营敌对关系、邻接、指挥点、行动次数和目标省份。
2. 锁定参战单位与结算前资产快照，聚合同省协同部队，但保留各自 `entityId`。
3. 计算人员、火炮、坦克基础战力和地形效果。
4. 应用训练、有效士气、补给、共和国军事化、工事、难度和随机系数；每个乘区只执行一次。
5. 比较最终战力，确定胜负、士气变化与撤退资格。
6. 按各参战单位战力贡献比例分摊人员与重装备损失；余数分配给贡献最高的单位。
7. 处理撤退、包围缴获与省份所有权；缴获进入实际占领单位所属实体。
8. 写入资产账本和战报，再依次检查阵营败亡、五月危机及战争结局。

共和国军事化固定表仍为 L0 `1.00 / 0 / 1.00`、L1 `1.05 / +5 / 0.95`、L2 `1.10 / +10 / 0.90`。该修正从全局状态动态读取，不写入单位，也不与旧 `militarization` 字段叠乘；第三阵营成立后不再享受共和国军事化修正。

### 13.2 胜利条件

- 阿斯图里亚斯采用局部目标与短期坚持，不再要求跨越半个西班牙占城。
- 西班牙内战的阵营败亡使用首都与剩余战略价值组合；交通线和有效军事实力影响实际战斗与补给，不再作为隐藏的第三项投降门槛。
- 第三阵营的最终胜利条件只有一个：共和国与国民军均已进入败亡状态。不能通过谈判承认、仅守住加泰—阿拉贡—瓦伦西亚或只击败其中一方取得胜利，也不再附加一份必须同时控制的战略城市清单。
- 三个阵营始终两两敌对。三方阶段不提供停战、共同作战、临时互不侵犯或单独媾和；任一阵营败亡后，剩余两个阵营继续互相作战。
- 共和国与国民军可以先后出局，且不要求都由第三阵营直接触发投降。如果共和国先被国民军击败，其剩余领土并入国民军；第三阵营随后击败扩张后的国民军，仍视为两个敌对国家均已败亡并完成统一。
- 败亡条件固定为：共和国失去马德里、巴塞罗那、瓦伦西亚且剩余控制区战略价值 `<50`；国民军失去布尔戈斯且剩余控制区战略价值 `<60`；第三阵营失去分裂时确定的革命首都且剩余控制区战略价值 `<50`。巴塞罗那转入第三阵营时必定是革命首都。战略价值只统计当前由该阵营所有的省份。
- 任一阵营满足败亡条件时，读取其首都省份当前所有者作为 `capitalOccupier`，再把该阵营所有尚存省份原子转交给 `capitalOccupier`。已经被其他阵营占领的省份保持当前所有权，不被二次改色。
- 首都无人占领、首都所有者仍是败亡方或首都数据缺失时，败亡检查返回 false，不得执行结算。每次占领首都时同时保存 `capitalCaptureEntityId`，用于确定之后的缴获归属。
- 省份必须有至少 `1` 支本方非重部署单位驻扎，才提供 `100%` 战略价值、工业和普通兵源；无驻军控制省只提供 `50%` 战略价值与工业且不提供普通兵源。败亡阈值使用折算后的战略价值，抑制少量部队吞并空地滚雪球。

败亡结算是一次不可中断事务，顺序固定如下：

1. 将败亡阵营状态置为 `defeated`，冻结命令、生产、征募、补充、事件军援和 AI 行动。
2. 将其仍有所有权的省份转交 `capitalOccupier`，并按新领土实时重算地方工业与兵源；既有敌占区不改色。
3. 汇总败亡阵营所有地图部队、活动实体池和回收队列中的人员、火炮、坦克，然后删除地图部队、关闭实体池，保证原资产不再可用。
4. 人员的 `70%` 进入占领者的非战斗战俘账本，`30%` 记为复员、逃散或死亡；战俘不能自动进入任何武装池，只能由后续明确事件处置。
5. 火炮和坦克各有 `50%` 立即作为可用缴获，`25%` 进入占领者 `1` 回合维修队列，`25%` 永久损失。
6. 败亡方中央补给与 `centralIndustrialReserve` 同样按 `50%` 立即接收、`25%` 延迟 `1` 回合接收、`25%` 损失；由省份实时产生的工业不参与本步，避免重复。
7. 可用及维修后的缴获进入 `capitalCaptureEntityId` 对应实体；若该实体已经失效，则共和国或国民军缴获进入各自国家武装池。第三阵营不得建立“委员会总池”：其缴获只能进入实际攻占首都的 CNT 或 POUM 实体；缺失合法来源实体时资产留在维修队列，直到该阵营一支合法实体部队进入首都后领取。
8. 取消败亡方未抵达外援；已抵达资产已包含在地图部队或实体池汇总中，不重复计算。
9. 写入逐项交易记录并执行非负、总量守恒和唯一归属断言，然后检查剩余阵营。剩余两方继续互战；仅剩一个活跃阵营时才结束全国战争。

共和国、国民军和第三阵营的败亡标记各自持久保存，不能用单一 `civilWarStatus` 在第一方投降时提前结束三方战争。第三阵营只有在共和国与国民军两个败亡标记都为 true 时取得“统一全国”胜利；若第三阵营先败亡，则按最终存活的共和国或国民军结局收束。

玩家当前控制阵营败亡时立即进入该路线的失败结局，不要求玩家旁观剩余 AI 战争；但败亡事务仍须先完整结算，保证结局存档一致。普通共和国—国民军两方战争中，一方败亡即由另一方获胜；三方战争中，只有 AI 阵营败亡时地图玩法继续，直到玩家阵营胜利或败亡。

### 13.3 海外与孤岛

非洲军团渡峡、岛屿和海上封锁必须由事件/海运通道处理。不能让关键历史力量因地图无邻接而永久困住，也不能允许普通陆军跨海无成本移动。

## 14. UI 与玩家反馈

战争界面只增加必要信息：

- 选中单位：所属武装实体、人员、火炮、坦克、士气、战斗训练度；军事化等级及其三项当前修正在共和国战争总览中只显示一次。
- 征募/补充：选择实体后显示该池余额，以及阵营补给和工业成本。
- 战争总览：各实体前线资产与预备池，不把政党支持率伪装成兵力。
- 三方战争总览：分别显示共和国、国民军和第三阵营的败亡进度，以及当前首都占领者；第三阵营只在另外两个阵营均已败亡时显示总胜利。
- 月结：显示资产流入来源、战损、缴获、整编转移和凝聚力变化原因。
- 五月危机：显示触发原因、接受整编或全国抵抗会转移哪些民兵池、部队、资产和省份。
- CNT 组织面板：`DC` 成立后显示防御委员会；`MC` 只有在 1936 年战争动员成立后才新增显示，成立前不放置灰色占位或预告槽。
- 非 CNT 组织：`uiVisibility: 'internal'` 的组织不得出现在组织面板、党派页面、百科状态、卡牌目标、提示框或月结组织清单。对应武装实体在战争界面仍以历史部队名称显示，因为玩家需要识别和补充部队；这不暴露其内部组织状态。

不在普通攻击按钮旁显示政治授权、服从概率或党派命令费用。

## 15. AI 规则

- AI 与玩家调用相同的征募、补充、整编、缴获和成本函数。
- AI 先决定需要的编制，再选择拥有对应人员/火炮/坦克的实体；不得硬编码生成 `gov` 单位。
- 共和国 AI 在分裂后优先保卫马德里与交通线，国民军 AI 优先连接南北控制区，委员会 AI/玩家优先保卫加泰—阿拉贡—瓦伦西亚走廊。
- AI 不得把所有省份月度人力同时注入每个实体；国家兵源进国家军，党派兵源由各自组织渠道产生。
- Easy 仍会征募、补充和守关键点，只降低进攻性与资源效率；不能关闭整个军事行为集。

AI 每回合按同一优先序消费指挥点：解除首都直接威胁、恢复补给线、补充低于 `50%` 编制的单位、为无防 `strategicValue >= 7` 省份建立守军、攻击、建设。攻击目标评分固定读取“胜率、战略价值、工业、补给线缩短、首都威胁、包围收益”，不得读取玩家不可见的未来事件结果。

实体选择遵循以下规则：国家池承担普通征兵与无指定来源的生产；地区民兵优先在合法征募区补充；外国实体只使用自身人员与装备；同等可行时优先补充当前编制率最低且正在保卫高战略点的实体。共和国 AI 的军械分配同时计算联盟凝聚力，不得为追求即时战力而无限偏袒单一集团。

三方战争行动顺序每月轮换先手，防止固定第三行动方长期吃亏。Easy、Normal、Hard 的搜索深度分别为 `1/2/3`，AI 战力系数按第 13.1 节执行；三档都使用相同合法性、成本、资产守恒和败亡规则，不获得隐藏人员或装备。

## 16. 主要失衡风险与缓解

| 风险 | 机制原因 | 缓解方案 |
|---|---|---|
| 战前准备决定一切 | 五年积累直接线性变成开局师 | 使用历史基本盘＋阈值奖励，并限制额外骨干数量 |
| 玩家故意不给盟友装备 | 全指挥下弱化其他实体没有战术代价 | 战区覆盖、实体专属征募与凝聚力共同惩罚长期偏袒 |
| 国家军成为唯一最优池 | 集中装备效率更高 | 自主民兵提供地区征募、革命政治和危机路线价值 |
| 党派池断粮导致无法游戏 | 补充严格锁定来源 | 历史基础回补、志愿者事件和有代价的国家转隶 |
| 全局军事化抹平派系差异 | 一个等级同时作用于所有党派池 | 等级保持全局，但事件文本、政治代价与各党反应分别结算；不新增服从度 |
| 三级修正与训练度重复乘算 | 全局等级和单位训练度同时提高战力 | 明确两个独立乘区并压低阶段数值；全局修正只在战斗入口读取一次 |
| 高士气部队浪费阶段士气加成 | 有效士气在 100 封顶 | 保持封顶以防精锐过强，并在战斗预览中显示实际生效值而非名义 `+5/+10` |
| L2 后仍凭空分出 CNT 军队 | 人民军化已删除党派池和单位身份 | 明确 L2 对五月武装抵抗的影响；禁止按支持率重新造兵 |
| 玩家刷卡过早建成人民军 | 可重复军事卡直接推进制度等级 | 等级只由一次性历史事件推进；卡牌不写入全局军事化状态 |
| 五月事件每局必爆 | 军事失衡持续扣凝聚力 | 单月结构扣分封顶，重大事件才越界，提供调停与分配修复 |
| 三方化让国民军必胜 | 共和国一经选择抵抗便立即全国分裂 | 用严格触发门槛、真实资产、动态控制区和战略点储备分割限制初始差距，不使用停火保护 |
| 统一西班牙路线过长或不可达 | 第三阵营必须面对两个国家级敌手 | 使用败亡机制而非逐省清图；不附加额外城市清单，并允许另一敌对阵营先吞并一方后再由第三阵营击败最终对手 |
| 首都占领导致瞬间领土雪球 | 败亡方剩余领土全部转给首都占领者 | 败亡必须同时满足首都与衰败阈值；部队、人员和重装备不随领土自动转移 |
| POUM 加入路线在直开局中过难 | 1936 场景关系从 50 起步而门槛为 70 | 保证至少两条战时行动能在五月危机前累计 20 点关系，并在关系 UI 中预告 70 门槛 |
| 战略点分割制造或重复计算资源 | 本地工业转移后又参与中央储备切分 | 分裂前冻结快照、排除属地资源、逐项向下取整并执行总量守恒断言 |
| 分裂前抢占高战略点城市成为唯一最优解 | 中央储备份额完全由地图战略点决定 | 严格遵守无上下限比例，但领土转移仍受三区和 CNT 单独占有条件限制，不能只靠一支部队临时踩城改写全部版图 |
| 国民军派系过度戏剧化 | 对称系统诱导双方都内战 | 国民阵营基础路线走强制统一；全国分裂仅为极端架空结果 |
| 首都陷落后的缴获形成二次雪球 | 败亡结算一次性释放大量装备 | 仅 50% 立即可用、25% 延迟维修、25% 损失，人员只作为不可征募战俘记录 |
| 公共补给掩盖装备来源 | 池不记录轻武器和弹药 | 公共补给只决定持续作战，人员与重装备仍按实体守恒；分配政治只统计可追踪的火炮、坦克和人员 |
| 资产重复计算 | 阵营总库、实体池、地图单位同时记账 | 资产守恒测试和统一交易函数；阵营资源不再保存人员/火炮/坦克总量 |
| 旧存档失真 | 旧 `identity` 和 `warPools.equipment` 语义不同 | 一次性归一化迁移，保留旧字段读取但只写新结构 |

## 17. 存档迁移与实施分期

### 17.1 存档迁移

存档版本提升为 `militarySchemaVersion: 3`。迁移器只在版本小于 3 时执行，并在同一加载过程中完成以下步骤：

1. 按存档日期和场景建立完整组织名册，把旧 `established: boolean` 转为 `active/unformed`。保留现有 `DC` 日期；`poum_founded` 同步到 `POUM_PARTY`，`falange_jons` 同步到 `FALANGE_FIRST_LINE`，其余非 CNT 组织按第 4.5–4.6 节历史快照水合。
2. 建立稳定实体表和 `WarState`；未处于战争的存档只建立当时已合法存在的战前实体与准备状态，不启动地图战争。
3. 将旧 `Army.identity` 映射为 `entityId`：`gov -> republic_state_arms`、`cnt -> cnt_fai_militias`、`ugt -> ugt_socialist_militias`、`pce -> pce_maoc_fifth_regiment`、`poum -> poum_militias`、`intl -> international_brigades`。国民军旧 `gov` 按阵营改为 `nationalist_peninsular_army`。
4. 若旧战争存档已存在某党派地图部队，迁移器必须先按历史顺序补齐其组织链，再激活实体。例如旧 CNT 部队要求先 active `DC`、再 active `MC`；不得只为通过校验而跳过前置。早于组织历史窗口却出现对应部队的存档停止载入并报告错误。
5. 每支旧部队的 `manpower` 取 `max(旧 manpower, infantry + artillery + tanks)`；新火炮为 `floor(旧 composition.artillery / 100)`，新坦克为 `floor(旧 composition.tanks / 100)`；设计上限用同样规则转换。
6. 将旧 `militarization` 原值限制到 `0–100` 后写入 `combatReadiness`，删除其战斗读取路径；共和国全局军事化按日期和已触发事件恢复，无法证明已升级时使用 L0，不凭日期自动补发政治选择。
7. 将 `mapResources.manpower` 与 `tankReserve` 分别移入对应国家武装池的人员和坦克；`supplies`、`commandPoints` 原值保留，`industrialCapacity` 改名迁入 `centralIndustrialReserve`。
8. 将旧 `warPools.reserves[identity]` 迁入已经通过组织门控的对应实体人员，`warPools.equipment[identity]` 全部迁为对应实体火炮，避免与已有 `tankReserve` 重复制造坦克；随后删除旧 `warPools`。
9. 按第 6.5 节迁移旧民兵、军备、战斗力和装甲车字段；每个来源生成一条 `legacy_migration` 账本记录。
10. `partyRelations` 数值原样保留并限制到 `-100～100`；迁移后所有写入统一使用该区间的帮助函数，POUM 门槛仍为 `70`。
11. 对战争中的存档执行组织前置、资产唯一归属、非负值、部队实体存在、阵营一致和地图敌对同省检查。无法合法归属的部队不得静默改为国家军，而是停止载入并给出可定位的迁移错误。
12. 全部校验通过后才写入版本 3；迁移函数重复运行不得再次成立组织、转移资产或增加交易记录。

旧 `civilWarStatus` 只用于恢复普通两方战争：`ongoing` 映射为双方 active，`won/lost` 映射为已结束结局。旧存档不可能合法包含第三阵营，迁移器不得仅凭低凝聚力自动创建三方战争。

## 18. 验收与测试

### 18.1 规则测试

- 任一交易后池不得为负。
- 征募、补充、解散和整编满足资产守恒。
- 每个池的人员、火炮、坦克必须分项读写和显示，不得用一个合成数值替代。
- 共和国军事化等级只能有一个全局值，任一党派池或地图部队不得保存可分歧的等级副本。
- 不同实体普通合并被拒绝；整编后资产只存在于继承实体。
- 正规军、突击卫队和国民共和国卫队从同一个国家武装池征募与补充，但保留各自 `serviceType`。
- 同一党派的不同纵队不得生成重复民兵池。
- 战斗损失不重复扣预备池。
- 缴获归属实际占领单位的实体。
- 国家生产、党派私援和外国部队援助进入不同目标。
- 固定随机种子下，战斗严格按第 13.1 节顺序结算；军事化、训练、士气、地形和难度均只应用一次。
- 人员变化不隐式改变火炮或坦克，火炮和坦克也不计入人员总数。
- 无撤退路径时的额外损失、缴获和延迟重部署三者之和等于结算前剩余资产。
- 无驻军省份只提供 50% 战略价值与工业且不提供普通兵源；驻军进入后恢复 100%。

### 18.2 历史场景测试

- 1934 年开局不出现 POUM、第五团、国际纵队或人民军。
- 1934 年工人联盟三个党派池保持独立，统一指挥不得改变资产归属；镇压方全部兵种从同一共和国国家池补充。
- 阿斯图里亚斯胜负只读取当地目标与短期坚持。
- 1936 年 7 月开局不出现国际纵队和成熟人民军。
- 1936 年秋后才能整编混合旅、接收国际纵队。
- 1937 年初第五团可转入人民军。
- L0 -> L1 不得关闭或转移任何党派池；L1 -> L2 时全部党派池及所属部队必须在同一事务中并入国家池，且三项资产分别守恒。
- 军事卡反复使用不能推进 L0/L1/L2；两个等级变化只能由各自的一次性事件发生。
- 接受 L2 后五月危机不得显示武装抵抗选项；拒绝 L2 后等级保持 L1，且全部党派池原样保留。
- L0、L1、L2 分别派生 `1.00/0/1.00`、`1.05/+5/0.95`、`1.10/+10/0.90`，只应用一次、不写入单位、不改变武装池资产；第三阵营部队不得继续获得共和国修正。
- 1937 年 4 月国民阵营检查统一法令。
- Historical 模式在 1937 年 5 月检查五月事件；非历史模式按条件触发。

### 18.3 路线与平衡测试

- 低、中、高三档战前准备都能进入可玩战争，高准备有优势但不能锁定胜局。
- 共和国正常路线可以避免三方化；低凝聚力路线能稳定看到危机预警。
- 历史收敛、调停和直接全国抵抗三条路线都能完成。
- 选择全国抵抗后不得进入巴塞罗那局部地图战，第三阵营必须在同一次事件结算中成立。
- 三区内共和国省份只有在不存在非 CNT 驻军时才转入第三阵营；国民军占领区不得因区域标签改色。
- 三区外省份只有在由 CNT 部队实际单独占有时才转入第三阵营，党派支持率不得替代驻军事实。
- 混合驻军省份必须留在共和国；其中 CNT 部队在第三阵营首回合前完成有序撤离或进入有损延迟重部署，地图不得出现敌对同省状态。
- POUM 只有在已成立、仍合法、未受镇压且关系至少 70 时整池加入；其加入不得扩大领土快照。UGT/PSOE 与 PCE 必须整体留在共和国。
- 三方分裂时本地资源只随省份转移一次；中央补给和可转移工业储备按双方控制城市的战略点数之比切分并保持总量守恒，国民军占领区不进入分母，未抵达外援进入暂停重判状态。
- 战略点比例不设上下限：分别测试第三阵营份额 `0%`、`100%` 与 `C + R = 0`；最后一种情况中央储备全部留共和国。
- 三个阵营始终两两敌对，不得停战或媾和；任一阵营败亡后，剩余两方继续战争。
- 败亡方尚存省份全部转交败亡瞬间的首都占领者，既有占领区不二次改色；部队和池资产不得随领土隐式复制。
- 三个阵营分别在阈值上下边界测试败亡：`<50/<60/<50` 触发，等于阈值不触发；首都未被合法敌方占领时不触发。
- 败亡人员严格按 70% 战俘、30% 损失结算，火炮、坦克、中央补给与中央工业储备严格按 50% 即用、25% 延迟、25% 损失结算。
- 第一方败亡后全国战争仍保持 active；只有剩一个活跃阵营时进入 resolved，第三阵营必须同时看到共和国与国民军败亡标记才获胜。
- 第三阵营只有在共和国与国民军均已败亡时胜利，不附加额外战略城市控制清单；消灭其中一方或取得谈判承认不得提前结束战争。
- 国民军普通历史路径能够完成统一，不会因对称系统高概率自爆。
- Easy、Normal、Hard 的 AI 都会进行基本征募、补充和防御，差异来自效率与风险偏好。

### 18.4 工程约束

- 卡牌和事件不直接整块覆写地图或武装池，统一调用领域函数。
- 事件 ID 保持稳定；新增事件使用 `snake_case`，中英文本和条件提示齐全。
- AI 与玩家使用同一成本和合法性检查。
- 旧档读取时归一化 `identity -> entityId`，并迁移旧 `warPools`。
- 版本 2 旧档迁移到版本 3 后再次载入，资产数值与交易记录不得二次增长；非法归属必须显示迁移错误而非静默改成国家军。
- Historical 事件按准确月份与条件触发；Easy/Normal/Hard/Sandbox 忽略单独 `date`，依赖显式条件；事件 `meta` 不参与运行时判定。
- 地图战报必须渲染资产流向、战损和占领结果。

## 19. 历史性审校清单

### 19.1 历史锚点与有意抽象

- **阿斯图里亚斯 1934**：UHP 提供联合政治与指挥框架，但起义的社会主义矿工、地方 CNT 和共产主义组织并非同一财产主体，因此统一操作、资产分池；社会主义矿工仍是数量与地方组织主力。
- **共和国军事化**：1936 年秋至 1937 年的混合旅、民兵军事化和人民军形成是地区不均、充满冲突的过程。三级全局状态是制度成熟度抽象，事件文本和资产转隶必须保留第五团解散、CNT 纵队抵触、中央政府施压等差异，不能叙述成同日自愿合并。
- **国际纵队与苏援**：国际纵队有独立人员来源，苏联和墨西哥正式援助属于共和国国家渠道；PCE 可能获得政治影响，但不会自动取得国家援助的私有产权。
- **五月事件**：史实冲突主要发生在巴塞罗那并以共和国阵营内部政治重组和镇压收束。全国三方战争是明确的反事实升级，只有低凝聚力、拒绝人民军最终统一并主动抵抗才能进入。
- **POUM**：其在五月冲突中与 CNT 基层并肩并随后遭镇压；关系 70 衡量的是把整个组织投入全国决裂的意愿，不是一般政治同情。未达门槛时留在共和国只表示未整体加入第三阵营，后续仍可遭取缔和清洗。
- **国民阵营**：长枪党和卡洛斯派拥有真实民兵基础，但 1937 年统一法令表现为佛朗哥主导的强制整合。基础路线不把它镜像成另一场五月事件，只有极端架空条件才出现地图分裂。
- **败亡中枢**：共和国以马德里、瓦伦西亚、巴塞罗那三处政治中枢全部失守为条件，反映政府与战争重心的迁移；国民军以布尔戈斯为首都锚点；第三阵营优先以巴塞罗那为革命首都，无法取得时使用分裂快照确定的临时首都。阈值是玩法参数，不是历史兵力统计。

### 19.2 史料审校

实施具体数值和事件文本前，至少用两类史料交叉核对：

- 综合战争史：Hugh Thomas、Antony Beevor；
- 革命与共和国阵营内部：Burnett Bolloten、Ronald Fraser；
- 组织与地方研究：阿斯图里亚斯矿工运动、加泰罗尼亚五月事件、巴斯克军和国民军各派专题资料。

需要逐项核对的事实包括：组织成立/解散日期、地方兵力数量、外援抵达月份、军械来源、军队整编节点和实际控制区域。设计文档中的倍率与阈值属于游戏参数，不应冒充历史统计。

## 20. v3.0 Final 相对 v1.1 的关键修订

| v1.1 做法 | v3.0 Final 修订 |
|---|---|
| 以党派身份为主建立预备池 | 国家正规武装合为一池，各实际党派民兵各一池；兵种和具体纵队只保留在地图单位层 |
| 装备池含统一装备度/补给语义 | 每池严格只有人员、火炮、坦克；补给和工业留在阵营层 |
| `identity` 粒度较粗 | 使用可扩展 `entityId`，允许同一政治集团拥有多个真实武装实体 |
| 五月事件满足条件后可直接全国三方化 | 电话局危机提供政治选择；选择武装抵抗后直接进入全国三方战争，不设置局部战前置 |
| 军事化既像训练又像一次性整编 | 战斗训练度与全局三级军事化分离；L2 一次性统一三个资产栏和全部党派民兵部队为人民军 |
| 军事卡可承担制度整编 | L0/L1/L2 只由一次性历史事件推进；军事卡只处理训练、征募和地图部队改编 |
| 五月决裂缺少其他民兵站队规则 | CNT 必然加入、POUM 条件加入、UGT/PSOE 与 PCE 留共和国；每个池均整体结算 |
| 阿斯图里亚斯后置且沿用大地图目标 | 使用同一引擎的短回合局部战争，重写为历史合理的当地目标 |
| 国民军内部仅列入远期范围 | 建立 Requeté、长枪党、非洲军团和统一法令的实体与事件接口 |
| 兵员、炮兵、坦克在地图上共用人数尺度 | 人员与重装备分离，重写战斗和资产守恒语义 |
| 军事化收益与训练/编制语义混杂 | 三级制度状态直接提供固定战力、有效士气与伤亡修正，但只作为全局派生值应用一次 |
| 内部分裂后的公共资源缺少确定结算 | 本地资源随属地，中央储备按共和国与第三阵营控制城市的战略点之比守恒切分，未抵达外援重新判定 |
| 阿斯图里亚斯可抽象为单一 UHP 池 | 三个工人组织各自建池、联盟统一指挥，镇压方使用共和国国家池 |
| 第三阵营可采用生存或谈判目标 | 第三阵营必须等到共和国与国民军均败亡；不设额外城市清单，败亡方剩余领土转给首都占领者 |
| POUM 站队关系阈值未固定 | 固定为已成立、合法、未受镇压且 CNT-POUM 关系至少 70，整池加入或整池留下 |
| 三方阵营可出现临时外交安排 | 三方始终两两敌对，不允许停战、共同作战或单独媾和 |

本方案的核心不是增加更多政治数值，而是让“谁实际掌握武装”成为战争、资源分配、整编和内部决裂共同读取的同一事实源。
