## 1. 背景与问题

### 1.1 现状摘要（来自源码审阅）

`stats.workerControl` 目前是一个 0–100 标量（`src/game/types.ts:421`，初始 10，见 `GameContext.tsx:692`），全代码库**只有一个机制消费者**：

```ts
// src/game/rules/income.ts:22
resources: INCOME_RULES.baseResources + Math.floor(state.stats.workerControl / INCOME_RULES.workerControlBand)
// baseResources = 1，workerControlBand = 20 → 每 20 点 +1 资源/月，上限 +5
```

它不进入内战触发公式（`GameContext.tsx:1536-1543` 的 tension 只由 共和国权威 / 军队忠诚 / 革命热情 组成）、不进入 `calculateMonthlyPolicyEffects`、不进入 `calculateEconomicPoliticalFeedback`、不进入派系影响与选举。同时它的语义与三个既有系统重叠：

| 既有系统 | 位置 | 重叠点 |
|---|---|---|
| `revolutionaryFervor` | `stats` | "革命进展"已被占用，且有 tension 出口 |
| `domesticPolicy.union_status` level 4「委员会控制」 | `rules/policyDefinitions.ts:125` | 文案为"工人委员会管理工厂"，效果栏写着"无月度效果"——重复且是空壳 |
| `classes.Obreros.support.CNT_FAI = 35` | `parties.ts:28` | 已经是"工人中支持 CNT 的比例"，零和归一化 |

三个具体缺陷：

1. **一个字段装三种语义**：工运规模（工会扩张 +2）、劳资制度权力（劳工事务 +8）、直接占有生产资料（加泰罗尼亚夺取 +20）混在同一个标量里，导致它既不能驱动工会竞争，也不能驱动政策，也不能驱动经济。
2. **数值不可控**：50 处效果写入点散落在 31 个内容文件（10 顾问 / 9 事件 / 8 行动卡 / 2 政府事务卡 / 2 日志），步长 ±1…±20，无衰减、无月度量纲、无上限保护（仅靠 `GameContext.tsx:1505` 全局 clamp 兜底），且因乘法系数产生小数（Bug 报告 B-13c：顶栏 `11.68%` vs 侧栏 `12%`）。
3. **历史锚点缺失**：1931 开局 10 点，而"工人控制工厂"在 1931 年不存在；真正的 `control obrero` 是 1936 年 7 月之后的产物。同一标量跨越 1931→1939 必然双向失真。

### 1.2 本方案要解决什么

把当前这个混合标量**拆成两个独立字段**：

- **工会占比 `unionShare`**：六家真实工会 + 其他工会 + 未组织者的八项占比，平铺呈现"这个国家的工会格局"，并让**右翼工会（CNCA / CONS）对左翼工运形成掣肘**；
- **工人控制程度 `workerControl`**：工人对生产资料的**实际**控制程度，只在具备制度与事件支撑时才可能上升，并接上真实经济后果。

同时**解耦**所有与该两个概念不符的写入点（纯政治 / 军事 / 秩序类），让每个效果只写它真正影响的东西。

## 2. 目标与非目标

### 目标

- G1 **字段拆分**：`stats.workerControl` 移除，新增 `unionShare`（顶层向量）与 `stats.workerControl`（0–100 标量），旧存档经归一化无损迁移。
- G2 **八项占比**：`CNT / UGT / UR / ELA / CNCA / CONS / other / unorganized` 八项平铺，和为 100，**不按阶级分组**；六个具名工会与组织注册表耦合。
- G3 **右翼掣肘**：CNCA / CONS 合计为 `rightShare`，对罢工成功率、CNT 招募效率、土地改革、工人联盟门槛施加可感知的压制。
- G4 **侧栏新栏位**：侧边栏新建「工人控制程度」栏，同屏展示工会占比环形饼图、派生读数与工人控制程度条；**顶栏不再显示该指标**。
- G5 **写入点解耦**：50 处写入点按语义重新指向「工会占比 / 工人控制程度 / 革命热情 / 军事 / 权威」等真实归属，消除双重计数与语义错挂。
- G6 **工人控制程度成为经济杠杆**：进入失业 / 增长 / 通胀 / 财政目标公式，并受"制度支撑"约束。
- G7 **修复既有缺陷**：B-13c 精度口径统一；缓解 B-04 阿斯图里亚斯路线因门槛过窄而不可达。

### 非目标（本期不做）

- **不做阶级划分**：向量不标注"该组织代表哪个阶级"，也不按阶级分组显示——左右翼的对抗以"社会主导权"统一表达（§5.5）。
- 不做地区级占比细分（加泰罗尼亚 / 巴斯克 / 安达卢西亚各自份额）——列入 Backlog。
- 不做 UGT 内部派系（Caballeristas / Besteiristas）。
- 不改动内战的兵力生成与地图经济（仅提供占比作为动员上限的输入）。
- 不引入"工会会员绝对人数"这一独立字段。
- 不重写 `union_status` 政策等级（P4 只做与 `workerControl` 的打通）。

## 3. 设计原则

1. **语义单一**：一个字段只回答一个问题。`unionShare` 回答"谁组织工人"，`workerControl` 回答"谁管理生产资料"。
2. **平铺不分类**：八项一律平铺，左翼与右翼组织使用同一口径、同一分母；对抗关系由机制（§5.5）表达，不由标签表达。
3. **占比即绝对力量**：`unionShare` 的分母固定为"全国体力劳动者总盘"（工人 + 雇农 + 小农 ≈ 69% 人口），因此 CNT 分量本身就等于"CNT 吸纳了全体体力劳动者的百分之几"，无需二次换算。
4. **增长必有来源**：CNT 的每一分增长都必须明确来自"同侧对手工会"（成员竞争）、"右翼工会"（主导权转移）或"未组织者"（招募）。
5. **制度支撑原则**：`workerControl` 不是进度条而是状态——缺少 `union_status` 或集体化事件支撑时自然衰减。
6. **复用既有算法**：零和归一化直接抽取 `utils/classSupport.ts:39-148` 的 `adjustSingleClassSupport`，不新写一套。
7. **编译期强制审计**：移除 `workerControl` 键后，50 处写入点、`effectPreview.ts` 的 `STAT_LABELS`、`rules/policy.ts` 的 `StatKey` 全部编译报错，这本身就是解耦工作的检查清单。
8. **分期可回滚**：每期结束都有明确的验证命令与回滚点；P0/P1 只做字段与 UI，不改任何玩法公式。

## 5. 概念模型：两根正交的轴

### 5.1 为什么必须拆成两个字段

西班牙 1931–1936 的工人运动有两条彼此独立的冲突线：

```
        ┌────────────────────────────────────────────────────────────┐
        │  字段一 工会占比 unionShare（谁组织工人）                   │
        │  CNT ⟷ UGT ⟷ UR ⟷ ELA  ∥  CNCA ⟷ CONS  ⟷  other ⟷ 未组织  │
        │  出口：会费收入、党派关系、UHP/Alianza、民兵构成、右翼掣肘  │
        └────────────────────────────────────────────────────────────┘
                              ⟂ 正交
        ┌────────────────────────────────────────────────────────────┐
        │  字段二 工人控制程度 workerControl（谁管理生产资料）        │
        │  0–100，1936.7 后才可能显著上升                             │
        │  出口：经济指标、地区控制、内战动员                         │
        └────────────────────────────────────────────────────────────┘
```

四种真实组合，单一标量无法表达：

| 时期 | 工会占比 | 工人控制程度 | 说明 |
|---|---|---|---|
| 1931 | CNT 占优、组织化率低 | ≈ 0 | 工团强大但无生产控制 |
| 1934 阿斯图里亚斯 | CNT+UGT 联合 | 短期骤升 | 起义期间的实际控制 |
| 1936.7 加泰罗尼亚 | CNT 主导 | 急速上升 | 集体化高潮 |
| 1937.5 之后 | CNT 份额被压缩 | 被行政接管 | UGT/PCE 上升，控制度回落 |

### 5.2 字段一：工会占比 unionShare（八项，平铺）

| 键 | 全称 | 中文 | 关联政党（owner） | 阵营 | 历史定位 |
|---|---|---|---|---|---|
| `CNT` | Confederación Nacional del Trabajo | 全国劳工联合会 | `CNT_FAI` | 左翼 | 无政府工团主义；城市工业 + 安达卢西亚农业 |
| `UGT` | Unión General de Trabajadores | 劳动者总工会 | `PSOE` | 左翼 | 社会主义；城市工业 + 阿斯图里亚斯矿区 |
| `UR` | Unió de Rabassaires | 拉巴塞尔联盟 | `ERC` | 左翼 | 加泰罗尼亚葡萄佃农 |
| `ELA` | Eusko Langileen Alkartasuna | 巴斯克工人团结工会 | `PNV` | 左翼 | 巴斯克民族主义 + 天主教社会路线 |
| `CNCA` | Confederación Nacional Católica Agraria | 天主教农业联合会 | `AP` | **右翼** | 天主教农业业主与佃农（1916 成立） |
| `CONS` | Central Obrera Nacional-Sindicalista | 国家工团工会组织 | `FE` | **右翼** | 长枪党的国家工团主义工会（1934-06 成立） |
| `other` | 其他工会 | 其他小型工会 | — | — | 伪桶：CNT 反对派工会、地方性工会 |
| `unorganized` | 未组织 | 未组织劳动者 | — | — | 伪桶：招募与流失的吸收池 |

> **平铺原则**：表中"阵营"列仅用于机制计算（`leftShare` / `rightShare`），**不用于 UI 分组、不写进数据结构**。八项在数据与显示上完全平等。

**口径与派生量**：

```
分母        = 1（全体；不再区分阶级）
份额约束    = 八项之和恒为 100
未组织下限  = unionShare.unorganized ≥ 15   ← 招募池下限，也是"完全组织化"的天然上限
绝对力量    = unionShare.CNT
组织化率    = 100 − unionShare.unorganized
左翼合计    = CNT + UGT + UR + ELA + other
右翼合计    = CNCA + CONS                      ← 掣肘系数
CNT 主导度  = CNT / leftShare                  ← 左翼工运内部的领导权
```

**口径说明（v1.4 简化）**：不再为向量指定任何阶级分母——八项之和即全部，分母视作 1。`unorganized` 钳制在 [15, 100]：它既是招募与流失的吸收池，也保证"完全组织化"不可能发生（任何时刻至少 15% 的人不在任何组织手中）。数值是**相对权重**（组织力量分布），不声称人口学准确性。

### 5.3 字段二：工人控制程度 workerControl

语义限定为"工人对生产资料的**实际**控制程度"，并加三条约束：

1. **时间闸门**：1936 年 7 月之前，上限 40（此前的集体化是零星、局部的）。
2. **制度支撑**：`union_status < 2` 且未发生任何集体化事件时，每月自然衰减 −1。
3. **不可逆性**：一旦发生重大集体化事件（加泰罗尼亚夺取 / 阿拉贡委员会 / 土地集体化日志完成），衰减停止，闸门抬升到 100。

### 5.4 两字段的交互（单向）

| 条件 | 效果 |
|---|---|
| `cntDominance ≥ 60` 且 `workerControl ≥ 50` | 每月 `bureaucratization −1` |
| `cntDominance < 40` 且 `workerControl ≥ 50` | 每月 `bureaucratization +1` |
| `leftShare ≥ 60` | `strike` / `mitin_popular` 成功率系数 +10% |

### 5.5 右翼掣肘机制（v1.3 新增）

**设计意图**：CNCA 与 CONS 不是"等着被 CNT 抢会员的池子"，而是**压在左翼工运上的反作用力**——它们占据乡村与右翼街区的社会主导权，抬高罢工成本、拖慢组织扩张、阻挠土地改革，并在关键时刻卡住工人联盟的成立。

**掣肘钩子**（系数为占位，P2 校准）：

| # | 钩子 | 公式 | 说明 |
|---|---|---|---|
| E1 | 罢工 / 集会成功率 | `− rightShare × 0.8`（百分点） | rightShare 10 → 成功率 −8pp |
| E2 | CNT 招募类效果缩放 | `delta × (1 − rightShare / 150)` | rightShare 15 → 招募效率 ×0.9 |
| E3 | 土地改革 / 农业集体化 | `rightShare ≥ 15` 时效果 ×0.5 | 乡村被教会组织把持，改革推不动 |
| E4 | 工人联盟（Alianza）门槛 | 追加 `rightShare ≤ 12` | 右翼工会坐大时，工人阶级统一战线无法成立 |

**右翼占比的动态来源**（保证它不是一个常数）：

| 方向 | 触发 |
|---|---|
| `rightShare ↑` | CEDA–激进党执政、土地改革失败或停滞、反教权暴力事件、FE 支持度上升、内战爆发后国民区整合 |
| `rightShare ↓` | 土地改革 / 农业集体化成功、CNT-FNA 在乡村扩张（U-对抗）、教会财产被没收、右翼政党被解散 |

**左右翼对抗的语义**：左右翼之间的份额流动（§8 的「U-对抗」类）表示**社会主导权的转移**，不是会员身份转换。当 CNT 在某地扩张，`CNT +1 / CNCA −1` 的含义是"该地区的乡村社会由教会组织主导转为由 CNT 主导"——这是一次抽象，但比"地主变成工人"合理得多。

## 11. 兼容性、测试与风险

### 兼容性

- `unionShare` optional，旧档经 `normalizeUnionShare` 兜底初始化。
- `stats.workerControl` **代码键保留**（语义收窄），旧档无需迁移；`unionShare` 为唯一新增字段，optional + 读取归一化。均无需 bump `SAVE_FORMAT_VERSION`。
- `effectPreview.ts` 的 `STAT_LABELS`、`rules/policy.ts` 的 `StatKey` 会因键变更而编译报错——属预期审计，非回归。
- `tsconfig.json` 未开启 `noUnusedLocals`，`TopBar.tsx` 遗留的 `Factory` 导入不会导致构建失败，但应在 P1 清理。

### 工程纪律

1. **单一规则源**：占比归一化只保留 `utils/zeroSumShare.ts` 一份实现。
2. **纯函数配测试**：`unions.ts`、`zeroSumShare.ts`、掣肘钩子必须有确定性用例。
3. **UI 与规则双轨同步**：门槛与掣肘数值同时出现在规则与 UI 提示文案，改动须一并更新。
4. **效果写入收敛**：新代码一律走 `adjustUnionShare` / `adjustControlObrero`，禁止直接写 `stats.workerControl` 或 `state.unionShare`。

### 主要风险

| 风险 | 缓解 |
|---|---|
| 50 处效果重写导致平衡漂移 | P2 按内容域分批合入，每批做 headless 前后对照 |
| 掣肘机制过强导致左翼路线普遍不可达 | E1–E4 系数低起步，先扫 `rightShare` 曲线再定标；掣肘读数在 UI 明示，避免"隐形惩罚" |
| `rightShare` 成为常数（缺乏动态来源） | §5.5 已列出升降来源；P2 必须接入至少两条（土改、选举/执政） |
| 左右翼份额流动被误读为"会员转换" | §5.5 明确语义为"社会主导权转移"；UI tooltip 同步说明 |
| 占比与阶级支持双重计数（如 `casas_viejas`） | §8.5 已标出，P2 一并清理 |
| 1933 剧本 Alianza 窗口仍过窄（B-04） | P2 必须回归该路线；必要时再放宽时间窗 |
| `workerControl` 经济耦合过强导致衰退螺旋 | 系数低起步，先跑曲线再定标 |
| 新增 4 个组织条目影响既有组织 UI / 武装链 | 全部 `uiVisibility: 'internal'` 且无 `armedEntityId`；P0 验证 |
