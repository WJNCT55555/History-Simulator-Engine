# 引擎与制作工具的边界

## 三个层次

1. 引擎接收 `GameProject` 和 `RuntimeState`，执行 `Command`，不导入 React、编辑器或具体游戏内容。财政和战斗为独立模块，表达式与份额转移为共享规则。
2. 项目是 JSON，使用作者指定的稳定 ID，包含初始世界、内容、条件、效果与规则参数。主体、群体、派系、组织的数量均来自数据。
3. 编辑器修改项目定义；试玩使用克隆后的定义快照；播放器负责展示和输入。两者使用同一引擎，不自行结算政治、财政或战斗。

规则入口位于 `src/engine/model.ts`、`simulation.ts`、`validation.ts`、`expressions.ts`、`economy.ts`、`combat.ts`、`shares.ts`。制作工具入口为 `editor/src/Studio.tsx`，通用游戏界面为 `src/runtime/Game.tsx`。

## 原子命令

`execute(project,state,command)` 克隆状态后检查阶段、权限、条件、费用与资产，执行写入、目标与结局检查，再校验状态。失败返回原状态与原因，AP、资源、随机状态和部队不会部分写入。效果预览在克隆上执行同一效果函数，读取变化。

卡牌入口费支付一次，选项只支付额外费用。政府事务在抽取和使用时均检查实际任职。强制事件未处理时不能切换阶段。事件队列与链内节点分开管理，普通调度不扫描链内节点。

## 月结顺序

```text
旧覆盖快照的组织收入
→ 推进年月，刷新 AP/手牌与战时生产、移动点
→ environment 周期规则（年度只在一月）
→ 财政与宏观
→ 法律月效果
→ society 周期规则
→ 组织与已启动目标的月效果
→ 选举与联盟维护
→ 冷却递减
→ 目标、成就、结局
→ 自动事件扫描
```

和平：事件 → 行动 → 月结。战争：事件 → 行动 → 战争 → AI → 月结。AI 同回合只执行一次，使用与玩家相同的移动/战斗规则；普通命令不产生月收入。

## 存档与军事来源

存档包含 RNG、当前决策及队列、事件记录、牌库、冷却、财政、制度、目标、军队来源等完整状态。必须匹配项目 ID、内容版本和定义指纹。修改定义后重新开局；当前版本不自动迁移不同项目或旧游戏的存档。

来源身份与当前阵营分开保存。来源转移时更改归属和现有同源部队阵营，后备/装备/伤亡账继续使用原来源 ID。拆并和解散不会复制资产。

## 文件与打包

本地服务接受稳定项目 ID，将通过校验的 JSON 原子写入 `projects/local/<id>/game.json`。不接收任意路径，不执行作者脚本；默认监听回环地址，禁止跨来源写入。

构建生成包含 React 和播放器的 IIFE，再与经过转义的项目 JSON、内嵌素材合成单文件 HTML。玩家运行独立游戏无需编辑器、保存 API 或 Node.js。

扩展规则时先定义状态/命令/效果及校验，再实现计算，最后接入制作表单和界面。权限必须由命令复核。结算顺序和公式变更需要有意义的回归证据，并同步文档与示例。
