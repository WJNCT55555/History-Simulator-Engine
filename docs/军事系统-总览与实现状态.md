> **本文档的定位**：军事相关内容目前散落在 8 份文档里，且其中数份描述的是"目标态"而非"当前代码"。本文档把它们归位，给出**以代码为准的实现状态**，并列出尚未完成的机制。
>
> **审计依据**：`src/` 全量检索 + `npm run verify:phase5` 全绿（`tsc --noEmit` + 权威性扫描 **252 个源文件** + 架构边界扫描 **213 个游戏源文件** + **15 个测试套件** + `vite build`；注册表 **30 张卡 / 69 个定时事件 / 168 个可恢复事件**）。每一条状态断言都标注了代码位置，可逐条复核。
>
> **最近一次复核：2026-09-24**（军事化 Phase 1/2/3/5 全部落地；两条日志、总事件与民兵合法性三级事件链均已实装；**P0 清单已清空**）。

## 2. 代码里的军事系统（权威结构）

### 2.1 状态字段（`GameState`）

| 字段 | 位置 | 含义 |
|---|---|---|
| `armyFormations` | `types.ts` | **和平期正规军编制表**（8 条）。和平期 `armies` 恒为空 |
| `armies` | `types.ts` | 战时地图单位。**只在内战/阿斯图里亚斯期间非空** |
| `armedForces.{guardiaNacional, guardiaAsalto, guardiaRepublicana, patrullasObreras}` | `rules/securityForces.ts` | 四支国家警察；存在与人力由 `security_corps_law` **派生**，忠诚由「警察事务」卡推动 |

| `militarization` | `types.ts` | **9 个派系的军事化率（0–100）**。同派系共享，单位不存副本 |
| `militarizationPaths` | `types.ts` | 军事化路线（`none`/`popular_army`/`militia_autonomy`）+ 选定时间 `chosenAt`。**不再有进度字段**——路线完成与否是状态条件，不是进度条 |
| `stats.armyLoyalty` | `types.ts` | 军官团忠诚（单一标量）；决定开战时陆军倒向哪一方 |
| `coupProgress` + `coupTriggered10..100` | `types.ts` | 政变暗流与 10 个里程碑 |
| `molaStatus` / `queipoStatus` / `francoStatus` / `africaArmyStatus` | `types.ts` | 四位关键军官与非洲军团的归属 |
| `mapResources` | `types.ts` | 阵营人力/工业/指挥点/补给/坦克储备 |
| `iberianDefense` | `map/types_map.ts` | **第三阵营（伊比利亚防卫）**的成立时间、盟友、淘汰记录、投降门槛 |
| `wartimePowerArrangement` | `types.ts` | 战时人民阵线联盟的路线、凝聚力与各成员承诺度 |
| `mayDays` | `types.ts` | 五月危机状态机 |
| `prepareRevolution` | `types.ts` | 「准备革命」卡的三条手段各自已用次数（`militiaUses`/`armyUses`/`sabotageUses`，各上限 3） |
| `military_policy_timer` / `prepare_revolution_timer` / `security_corps_law` 等 | `types.ts` | 卡牌冷却与法律等级 |

### 仍需你裁决的三个问题

**Q1 —— 军事化率与军事法律要不要挂钩？（已落地）**
**已决定并实现：挂钩。** `policyDefinitions.ts` 新增了 `PolicyModifier` 的 `militarization` kind，`policy.ts` 在月度结算里走 `adjustMilitarization` 唯一写入口。目前生效的等级：

| 法律 | 生效等级 | 月度效果 |
|---|---|---|
| `army_reform_law` | L3共和国人民军 | `gov` +0.5、共和国权威 +0.5 |
| `army_reform_law` | L4民兵纵队体系 | `cnt`/`ugt`/`poum` 各 +0.5、`gov` −0.3、革命热情 +0.5、权威 −0.5 |
| `militia_legality_law` | L2 / L3 / L4 | 民兵派系 +0.2 / +0.3 / +0.4（L3、L4 另有权威与热情代价） |

**剩下的问题**：`army_reform_law` 的 L3/L4 只能由两条军事化日志写到，而日志完成条件依赖 `militia_legality_law = 4` ——该前置已由三级事件链接通，**所以这张表已全部通电**。唯一仍不可达的是 `public_order_law` 的 L3/L4（属另一个系统，见 §3.1）。

**Q2 —— 军事化率的下限与上限是否要按派系区分？**
全局只有一个下限 10、上限 100，不按派系区分（**已接受**）。原先设想的"民兵自治会把民兵上限压到 55"已**废弃**，改为武装民兵路线的失败条件 `cnt > 60`。但右翼派系（Requeté/Falange）仍**既无上限约束也无成长**——建议一并处理 P1-2。

**Q3 —— `warRuntime` 占位留还是删？**
留着会持续误导后来者（类型看起来像已实现的状态机）。建议：要么在 Phase C 真做，要么删掉并让 `military-integration-design.md` Phase C 明确标为"已由五月危机替代"。
